# Структура репозитория

## Что утверждено

- Монорепозиторий. Один репозиторий на всю платформу.
- Язык — TypeScript.
- В репозитории живут: бэкенд-демон, фронтенд на React + Vite, общие пакеты и SDK-пакет для
  авторов плагинов.
- Система модульная: части отделены друг от друга и не лезут во внутренности соседа.
- Точка входа для разработчика — `make`: и dev-режим, и сборка.
- Рантайм — Node.js 24 LTS ([ADR-0002](adr/0002-nodejs-lts-as-runtime.md)).
- Менеджер пакетов — pnpm workspaces ([ADR-0003](adr/0003-pnpm-workspaces.md)).
- В dev-режиме поднимаются два процесса — Vite-сервер фронтенда и бэкенд, оба с хот-релоадом.
- Продакшн-сборка — единое приложение, запускаемое из терминала. В артефакт вшиты статика
  фронтенда и исходники встроенных плагинов; исходники разворачиваются в директорию данных при
  первом запуске версии
  ([ADR-0035](adr/0035-production-artifact-embeds-the-frontend-and-built-in-plugin-sources.md)).
- Раскладка — три корневых каталога ([ADR-0005](adr/0005-apps-and-packages-layout.md),
  [ADR-0036](adr/0036-built-in-plugins-live-in-a-third-root-directory.md)):

  ```
  apps/                    то, что запускает пользователь
    daemon/                ядро, веб-API, CLI
    web/                   веб-интерфейс, React + Vite
  packages/                то, что импортируют
    sdk/                   публичный контракт для авторов плагинов
    ui-kit/                примитивы интерфейса и токены темы, публичный пакет
    protocol/              схемы и типы API, общие для демона и веба
    agent-runtime-pi/      реализация агентного рантайма на Pi
  plugins/                 то, что демон загружает в рантайме
    <по каталогу на встроенный плагин, каждый — workspace-пакет>
  ```

  Направление зависимостей: `apps` зависят от `packages`, обратно — никогда. `plugins` зависят от
  `packages`, не зависят от `apps` и друг от друга, и не импортируются никем — их загружает демон.
  Правила проверяются автоматически.

- `ui-kit` — публичный пакет наравне с `sdk` ([ADR-0027](adr/0027-ui-kit-as-a-separate-public-package.md)).
  Он не импортирует `apps/*`, а `apps/web` строит оболочку и встроенные компоненты только из него:
  компонент, сделанный мимо кита, плагину недоступен. Отдельный от `sdk` он потому, что тянет React,
  а `sdk` не должен.

- Импорт `@earendil-works/*` разрешён только внутри `packages/agent-runtime-pi`
  ([ADR-0009](adr/0009-agent-runtime-behind-an-sdk-interface.md)). Интерфейс агентного рантайма
  объявлен в `sdk`, прикладной сервис поверх него — в ядре.

- Внутренние пакеты потребляются исходниками, без шага сборки
  ([ADR-0006](adr/0006-internal-packages-consumed-as-sources.md)). `tsc` — только проверка типов.
- Имена пакетов — в скоупе `@sovereign` ([ADR-0007](adr/0007-package-naming-scope.md)).

## Что из этого следует без выбора

Раскладка обязана разделять пять сущностей, потому что у них разные потребители:

| Сущность                        | Кто потребитель                                           |
| ------------------------------- | --------------------------------------------------------- |
| Демон (ядро + веб-API)          | конечный пользователь, запускает из терминала             |
| Веб-интерфейс                   | браузер пользователя                                      |
| SDK для плагинов                | автор плагина, внешний по отношению к репозиторию человек |
| Общий код (типы, контракты API) | демон и веб-интерфейс одновременно                        |
| Встроенный плагин               | демон, загружает его в рантайме на отдельном воркере      |

Отдельно: SDK — публичный контракт. Он единственный пакет, который увидят посторонние, и
ломать его дороже, чем всё остальное.

## Раскладка внутри каталога плагина

Платформа знает про плагин два места: `package.json` с полем `sovereign` — манифест с идентификатором,
точками входа и требуемым диапазоном версий платформы — и объявленные в нём точки входа
([ADR-0044](adr/0044-plugin-manifest-lives-in-package-json.md)). Как автор разложит остальные файлы,
платформу не касается.
