# ADR-0071: Plugin state is read through the plugin's own routes

- **Статус:** Accepted
- **Дата:** 2026-07-27

## Контекст

[ADR-0041](0041-bus-events-are-notifications-state-is-requested-from-its-owner.md) требует, чтобы у
каждого состояния, о котором публикуются события, был способ спросить «как сейчас».
[ADR-0061](0061-plugins-call-each-other-through-registered-procedures.md) ответил на это отдельным
механизмом: плагин регистрирует процедуры, ядро посредничает при вызове. Реализовано по нему ничего
не было — решение принято, кода нет.

Перед началом среза «плагинная часть шины» владелец продукта пересмотрел ответ. К этому моменту уже
принят [ADR-0053](0053-plugin-backend-access-routes-core-api-and-the-bus.md): у плагина есть
собственные HTTP-маршруты, и его же браузерная часть читает ими его состояние. То есть способ
спросить у плагина «как сейчас» в системе уже есть, и процедуры добавляют второй — для той же задачи.

## Решение

**Процедур не будет.** Отдельного механизма «вызов процедуры соседа» не появляется, вид вклада
«процедура» не заводится.

**Состояние плагина читается его собственными маршрутами (ADR-0053) — теми же, которыми пользуются
его вью.** Обязанность ADR-0041 закрывается для плагинов так же, как для ядра: у владельца состояния
есть публичный маршрут, по которому его состояние спрашивают. Кто спрашивает — браузер или сосед по
платформе — механизм не различает.

**Взаимодействие между плагинами остаётся двусторонним по смыслу и односторонним по механизмам:**
событие — чтобы рассказать, не зная соседа; маршрут — чтобы спросить, зная его.

**Вопрос об аутентификации вызова из воркера остаётся открытым.** ADR-0053 отверг «вызов маршрута
соседа» в том числе потому, что проверка сессии живёт в диспетчере и распространяется на маршруты
плагинов, а у вызова из воркера сессии пользователя нет. Направление изменилось, вопрос — нет: чем
воркер плагина предъявляет себя на маршруте другого плагина. Ответ нужен до среза маршрутов плагинов
и здесь не даётся. Соблазн ответить «пусть сосед объявит маршрут без входа»
([ADR-0065](0065-a-login-free-route-is-a-separate-public-route-contribution.md)) назван, чтобы быть
отвергнутым явно: маршрут без входа открыт наружу целиком, а нужна видимость только внутри
платформы.

## Альтернативы

**Оставить процедуры как есть (ADR-0061).** Механизм спроектирован, посредничество ядра даёт журнал,
таймаут и внятный ответ «некому ответить». Отвергнуто владельцем продукта: это второй способ сделать
то, что уже делает маршрут, и автор плагина каждый раз выбирал бы между ними без внятного правила.

**Процедуры только для запроса состояния, маршруты — для всего остального.** Границу можно объяснить
словами. Отвергнуто: она держалась бы дисциплиной, а не механизмом, — «состояние» и «действие»
различает только автор, и первый же плагин провёл бы черту по-своему.

**Ни процедур, ни чтения соседа: только шина, состояние публикуется периодически.** Отвергнуто ещё
в ADR-0061 и отвергается снова: это опрос, которого в системе нет по
[ADR-0013](0013-sse-for-server-initiated-updates.md).

## Последствия

- ADR-0061 переводится в `Superseded by ADR-0071`. Ничего, кроме статуса, в нём не правится.
- Вызов соседа теперь идёт кругом через HTTP-стек внутри одного процесса. ADR-0061 называл это ценой
  отвергнутого им варианта; цена принята сознательно — один механизм дороже одного лишнего хопа.
- Связность та же, что называл ADR-0061, и стала конкретнее: вызывающий знает не только идентификатор
  соседа, но и форму его маршрута. Это надо назвать в документации прямо, иначе автор будет считать
  чужой маршрут таким же безопасным способом связи, как событие.
- Обязанность «у состояния есть способ спросить» по-прежнему не обеспечена механизмом: ядро не
  проверяет, что у объявленного события есть парный маршрут. Проверяется обзором.
- В перечне публичных контрактов
  [ADR-0069](0069-breaking-change-is-a-removal-or-an-incompatible-change-of-the-declared-public-contract.md)
  строка «схемы событий и процедур ядра» теперь читается без процедур. Сам ADR-0069 не правится:
  принятые ADR не редактируются.
- Открытый вопрос про аутентификацию вызова из воркера становится блокирующим для среза маршрутов
  плагинов. До него взаимодействие плагинов ограничено шиной.
