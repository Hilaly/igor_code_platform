# ADR-0065: A login-free route is a separate public-route contribution

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[ADR-0053](0053-plugin-backend-access-routes-core-api-and-the-bus.md) дал плагину собственные
HTTP-маршруты и оставил проверку сессии в диспетчере — то есть у всего
([ADR-0026](0026-web-api-on-node-http-with-a-table-dispatcher.md)). Там же назван вопрос, который
надо решить до плагина вебхуков: входящий вебхук приходит без сессии пользователя, и способа объявить
такой маршрут у плагина нет. Сценарий 4 из [vision.md](../vision.md) без этого не работает.

## Решение

**Публичный маршрут — отдельный вид вклада.** Он объявляется не флагом у обычного маршрута, а другим
видом ([ADR-0054](0054-contributions-are-registered-per-kind.md)): «маршрут» и «публичный маршрут» —
разные вещи, и написать второе, имея в виду первое, нельзя случайно.

**Диспетчер пропускает проверку сессии только для этого вида.** Правило остаётся в диспетчере, а не
переезжает в обработчик: у обычных маршрутов ничего не меняется.

**Аутентификация публичного маршрута — забота плагина.** Платформа своей схемы не навязывает: GitHub
подписывает тело своим ключом, другой сервис носит токен в заголовке, третий не умеет ни того, ни
другого. Обработчик получает запрос как есть и решает сам.

**Публичные маршруты видны человеку.** Это единственная поверхность платформы, открытая наружу, и вью
плагинов обязано показывать её списком: какой плагин что открыл. Вклад при этом переключается, как
любой другой ([ADR-0032](0032-every-contribution-is-switchable.md)), то есть закрыть маршрут можно, не
выключая плагин целиком.

## Альтернативы

**Публичный маршрут с секретом от платформы: адрес выдаём мы, проверяем сами.** Открыть платформу
наружу по невнимательности было бы нельзя, а секрет можно перевыпустить. Отвергнуто владельцем
продукта. Цена варианта была в том, что адрес маршрута перестаёт быть свойством плагина: его надо
где-то узнать, куда-то скопировать руками, и он меняется при перевыпуске.

**Публичных маршрутов нет вовсе: кому нужен вебхук, слушает свой порт.** Поверхность платформы не
растёт. Отвергнуто: прямо противоречит ADR-0053 — плагин своего порта не открывает, — и оставляет
сценарий 4 без механизма.

**Флаг «без сессии» у обычного маршрута.** Меньше видов вкладов. Отвергнуто: разница между
защищённым и открытым наружу маршрутом слишком велика для булева поля, которое легко скопировать из
чужого примера вместе со значением.

## Последствия

- Ответственность за дыру целиком на авторе плагина, а последствие ошибки — открытая наружу машина
  пользователя. Значит документация SDK обязана описывать этот вид вклада не как удобство, а с прямым
  предупреждением, и первый наш публичный маршрут будет образцом, который скопируют.
- Стоит ли требовать отдельного включения человеком для вклада этого вида (в отличие от общего правила
  «вклад включённого плагина включён») — вопрос, который надо решить, когда появится первый такой
  маршрут. Сейчас он подчиняется общему правилу ADR-0032.
- Публичный маршрут доступен без входа, а значит его можно дёргать снаружи без ограничений. Лимит
  частоты и лимит тела для этого вида становятся не пожеланием, а частью механизма — иначе один
  публичный маршрут превращает демон в мишень.
- Появляется второй способ попасть в воркер плагина, минуя сессию пользователя. Журнал обязан
  различать эти вызовы от вызовов из интерфейса, иначе в логах не видно, что действие пришло извне.
