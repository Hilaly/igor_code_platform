# ADR-0016: User-controlled plugin enablement is the trust boundary

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Плагины распространяются исходниками, приносят свои npm-зависимости и исполняются с полными
правами процесса. Воркер — это изоляция от сбоя, а не от злого умысла: он ограничивает память,
но не запрещает читать файлы, ходить в сеть или писать в директорию данных.

Значит нужен ответ на вопрос, кто решает, какому коду можно работать.

## Решение

**Решает пользователь, по плагину.** У каждого плагина есть отдельная настройка «включён /
выключен»: доверенные включены, недоверенные выключены.

- Выключили — плагин выгружается. Включили — загружается.
- На старте демона поднимаются все включённые.
- Дальше действуют правила [ADR-0011](0011-plugins-run-as-supervised-workers.md): упал —
  перезапускается, изменился — перезагружается.

## Альтернативы

**Песочница с правами на плагин.** Правильный ответ в мире, где плагины ставят не глядя. Но
воркер не является границей безопасности, и настоящая изоляция потребовала бы отдельных
процессов плюс модель разрешений — по объёму это сопоставимо с самой платформой. Экспериментальная
модель разрешений Node сюда тоже не подходит: она задаётся на процесс, а не на воркер.

**Реестр доверенных авторов, подписи.** Не для системы с одним пользователем и плагинами,
которые он чаще всего пишет сам.

**Всё включено всегда.** Тогда защиты нет вовсе, а плагин из интернета получает полный доступ к
машине без единого вопроса.

## Последствия

- Граница доверия — факт включения, а не поведение плагина. Включённый плагин может всё, что
  может демон: файловая система, сеть, директория данных, чужие сессии через шину событий
  ([ADR-0012](0012-global-event-bus.md)). Это надо честно писать в документации для пользователя.
- Список плагинов и их состояние — часть состояния платформы и живёт в директории данных
  ([ADR-0008](0008-data-directory-config-and-instance-lock.md)).
- Выключение обязано быть полным: недостаточно остановить воркер, надо снять всё, что плагин
  зарегистрировал, — инструменты, подписки на хуки, подписки на шину. Значит ядру нужен реестр
  регистраций с привязкой к плагину, а не разрозненные коллекции.
- Открыто: в каком состоянии оказывается впервые обнаруженный плагин. Логика решения требует
  «выключен по умолчанию», но владелец продукта этого не говорил.
