# ADR-0049: The settings view writes config.json through the platform

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Владелец продукта описал вью настроек как место, где он правит настройки самой платформы, то есть
`config.json` ([vision.md](../vision.md)). Это вью поставляется встроенным плагином
([ADR-0047](0047-plugin-management-in-the-core-other-views-as-built-in-plugins.md)).

[ADR-0033](0033-config-and-preferences-are-separate-hot-reloaded-files.md) разделил настройки по
автору записи: `config.json` пишет человек редактором, платформа только читает; `preferences.json`
пишет платформа по нажатию в интерфейсе. Требование владельца в эту формулировку не укладывается.

**Уточняет ADR-0033** в части того, кто пишет `config.json`. Разделение файлов, механика
перечитывания, поведение при невалидном файле и правило про параметры, требующие перезапуска, остаются
в силе.

## Решение

**Вью настроек правит `config.json` через API платформы.** Платформа становится вторым автором записи
в этот файл — по явному действию пользователя, а не сама по себе.

**Разделение файлов остаётся прежним.** `config.json` — параметры развёртывания, `preferences.json` —
предпочтения. Меняется только то, что писать в первый разрешено и из интерфейса; смысл разделения был
в частоте и авторе изменений, а не в запрете.

**Запись сохраняет неизвестные ключи.** Файл, написанный более новой версией платформы или руками,
не обедняется записью из интерфейса: незнакомый ключ переписывается как есть. ADR-0033 уже требует
считать такой ключ диагностикой, а не ошибкой, — здесь то же правило со стороны записи.

**Запись атомарна** — временный файл и `rename`, как всё остальное состояние
([ADR-0020](0020-files-for-human-state-sqlite-for-machine-state.md)). Иначе наблюдатель директории
прочитает половину файла.

**Параметры, требующие перезапуска, правятся тем же путём.** Порт и путь к директории данных
записываются, но не применяются: диагностика «применится после перезапуска» из ADR-0033 работает
одинаково для правки руками и правки из интерфейса.

## Альтернативы

**Оставить `config.json` только на чтение, из интерфейса править лишь предпочтения.** Ноль изменений
в ADR-0033 и никакой потерянной правки. Отвергнуто владельцем продукта: он назвал правку настроек
платформы содержанием вью, а не его украшением.

**Показывать файл текстом и сохранять целиком.** Ни схемы, ни форм под каждый параметр — интерфейс
как редактор в браузере. Отвергнуто владельцем; отдельно замечу, что это и не снимает вопрос: писать
в файл платформе всё равно пришлось бы, только без пользы от интерфейса.

**Переложить правку `config.json` на ядро, а плагину дать вызов «сохрани это».** По сути то же самое,
что принято: API платформы и есть ядро. Разницы в решении нет, поэтому вариант не отдельный.

**Перенести всё в `preferences.json` и оставить `config.json` пустым.** Убрало бы противоречие
целиком. Отвергнуто: ADR-0033 разделил файлы именно потому, что нажатие переключателя не должно
перезаписывать файл с портом и путями; обратное слияние вернуло бы эту проблему.

## Последствия

- Одновременная правка руками и из интерфейса становится штатным сценарием, а не краевым. Побеждает
  последний `rename` (это уже записано в ADR-0033), и теперь это надо честно показывать в интерфейсе:
  файл мог измениться под открытой формой.
- У платформы появляется обязанность писать чужой формат бережно: порядок ключей и неизвестные поля
  переживают запись. Проверять это придётся тестом, потому что симптом — молчаливая потеря настройки.
- Права на файл настроек становятся частью работоспособности интерфейса: `config.json` только для
  чтения на диске даёт ошибку записи, которую надо показать внятно, а не как сбой сохранения формы.
- Вью настроек может выключить или заменить плагин. Значит правка настроек через интерфейс — не
  гарантия платформы; гарантией остаётся правка файлом, и это стоит сказать в документации для
  пользователя.
