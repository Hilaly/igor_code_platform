# ADR-0037: Platform hooks for session lifecycle, pre-start veto and turn accounting

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[agent-runtime-contract.md](../agent-runtime-contract.md) разделял наши хуки на утверждённые — запрос
разрешения у пользователя и сбор инструментов `tools_collect` — и на три предложенных агентом, по
которым решения не было. Предложение без явного «да» не является основанием для кода
([CLAUDE.md](../../CLAUDE.md), §8), поэтому три хука висели в документе без статуса.

Все три отсутствуют в Pi по определению, а не по недоделке: Pi получает `AgentHarness` готовым и не
знает ни о создании сессии, ни о её закрытии, ни о том, что турн для нас — единица учёта.

Владелец продукта утвердил все три.

## Решение

К двум уже утверждённым хукам добавляются три. Полный список хуков **нашего** слоя:

| Хук                                 | Что даёт                                                        |
| ----------------------------------- | --------------------------------------------------------------- |
| запрос разрешения у пользователя    | место для диалога подтверждения; ядро его не проксирует         |
| `tools_collect`                     | сборка динамического набора инструментов из включённых плагинов |
| `session_created`, `session_closed` | жизненный цикл сессии, которого Pi не видит                     |
| `before_session_start`              | политика **до** первой траты, с правом отказать                 |
| `turn_finished`                     | конец турна вместе с `usage` — единица учёта лимитов и бюджета  |

`before_session_start` — единственный хук, который может **отказать**. Отказ обязан приходить к тому,
кто запускал сессию, отличимо от сбоя: плагин, вызвавший запуск через SDK, должен видеть, что сессию
запретили, а не что она упала.

Тип `usage` в `turn_finished` объявляется в `sdk` как наш собственный, а не реэкспортируется из Pi:
импорт `@earendil-works/*` разрешён только внутри `packages/agent-runtime-pi`
([ADR-0009](0009-agent-runtime-behind-an-sdk-interface.md)). Иначе форма отчёта Pi протекла бы в
публичный контракт и меняла бы его при обновлении Pi.

## Альтернативы

**Обойтись событиями шины вместо хуков.** Жизненный цикл сессии можно было бы просто публиковать в
шину ([ADR-0012](0012-global-event-bus.md)), как публикуется жизненный цикл плагинов
([ADR-0018](0018-plugin-lifecycle-is-observable.md)). Отвергнуто для `before_session_start`: шина
односторонняя, отправитель не знает, слышал ли его кто-нибудь, и права отказать там нет по устройству.
Для `session_created` и `session_closed` события в шине тоже будут — но это наблюдение, а не точка
вмешательства, и одно другого не заменяет.

**Считать стоимость в ядре, без хука.** Ядро и так владеет сессиями
([ADR-0010](0010-core-owns-agent-sessions.md)), значит могло бы само вести лимиты. Отвергнуто:
это политика, а ядро даёт точки расширения, а не политику
([ADR-0015](0015-core-provides-extension-points-not-policy.md)). Какой лимит, что при его достижении
и кому показывать — решает плагин.

**Отказ на старте турна, а не сессии.** Точнее по деньгам: отказать можно перед каждой тратой.
Отвергнуто как замена: `before_session_start` дешевле и достаточен, чтобы не начинать работу вовсе.
Хук на старте турна не отвергнут по существу — он просто не понадобился до появления первого
потребителя.

## Последствия

- Хуки принадлежат нашему слою, а не Pi: обновление Pi их не задевает, но и переиспользовать его
  реализацию хуков для них нельзя — механику вызова пишем мы.
- Появляется хук с правом отказа, а значит вопрос о слиянии нескольких подписчиков перестаёт быть
  теоретическим: чей отказ побеждает, ждём ли всех, что при таймауте. Это часть уже открытого вопроса
  о порядке и слиянии хуков — здесь он не решается, но с `before_session_start` он становится
  блокирующим для кода.
- `usage` становится частью публичного контракта. Значит его форму придётся зафиксировать раньше, чем
  появится первый плагин, считающий бюджет, и она не сможет повторять форму Pi буквально.
- Право отказать выдаётся включённому плагину, то есть доверенному
  ([ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md)). Плагин, который отказывает всегда,
  ломает платформу — лечится выключением, как и любой другой вредный вклад
  ([ADR-0032](0032-every-contribution-is-switchable.md)).
