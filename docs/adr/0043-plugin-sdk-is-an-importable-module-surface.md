# ADR-0043: The plugin SDK is an importable module surface, not a context argument

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

`sdk` — единственный пакет, который увидят посторонние, и ломать его дороже всего
([repository-structure.md](../repository-structure.md)). Его **состав** к этому моменту уже определён
принятыми решениями: регистрация вкладов, подписка на хуки
([ADR-0039](0039-hook-results-merge-with-refusal-winning.md)), публикация и приём событий шины,
способ ответить о состоянии ([ADR-0041](0041-bus-events-are-notifications-state-is-requested-from-its-owner.md)),
журнал ([ADR-0021](0021-structured-logs-published-on-the-event-bus.md)), своё хранилище в директории
данных, запуск сессий агентов ([ADR-0009](0009-agent-runtime-behind-an-sdk-interface.md)), типы
`usage` и формы отказа хука ([ADR-0037](0037-platform-hooks-for-session-lifecycle-veto-and-turn-accounting.md)).
React в `sdk` не входит — он в `ui-kit` ([ADR-0027](0027-ui-kit-as-a-separate-public-package.md)).

Открытой оставалась **форма**: как плагин получает эти возможности. Ключевое обстоятельство — плагин
исполняется в отдельном воркере, по воркеру на плагин
([ADR-0011](0011-plugins-run-as-supervised-workers.md)), поэтому состояние модуля внутри воркера
принадлежит ровно одному плагину и живёт ровно столько же, сколько он.

## Решение

**Возможности SDK — импортируемые функции и объекты пакета `@sovereign/sdk`.** Плагин экспортирует
`activate` и, если нужно, `deactivate`, но возможности берёт импортом, а не из аргумента:

```ts
import { log, contribute, bus } from "@sovereign/sdk";
```

**Идентичность плагина приходит из воркера, а не из кода.** Бутстрап воркера — наш код — получает порт
к демону, инициализирует состояние модуля `sdk` и только после этого импортирует код плагина.
Объявить себя другим плагином невозможно: идентичность не является аргументом.

**Браузерная часть SDK вкладывается в бандл каждого плагина, а не шарится страницей.** Тогда хост
инициализирует её идентичностью этого плагина при загрузке бандла, и стиль API одинаков на обеих
сторонах. Синглтонами страницы остаются `react`, `react-dom` и фронтовая шина
([ADR-0017](0017-single-sse-connection-with-a-frontend-event-bus.md)) — наша прослойка к ним
синглтоном быть не обязана.

**Поставляется тестовый шов** — точка входа вида `@sovereign/sdk/testing`, подставляющая фальшивый
хост. Он обязателен, а не желателен: без него `import { log } from "@sovereign/sdk"` в юнит-тесте
автора работает с неинициализированным модулем. В документации SDK надо прямо сказать, что плагин в
тесте грузится через `await import()` **после** установки шва — импорты ESM поднимаются к началу
модуля, и обычный статический импорт выполнится раньше подготовки.

**Пакет один.** Дробим только тогда, когда к этому вынуждает зависимость, как это произошло с
`ui-kit`, вытащенным из-за React.

## Альтернативы

**`ctx` аргументом функции активации.** Граница видна: всё, что плагин может, он получил в аргументе,
и тест — это `activate(fakeCtx)` без всякой машинерии. Отвергнуто владельцем продукта. Взвешивая
честно: главный аргумент против `ctx` не в эргономике, а в том, что он не устраняет неявное состояние,
а перекладывает его на автора — любой файл плагина, которому нужен журнал или шина, обязан получить
`ctx`, и автор на второй день заводит `let ctx` на уровне модуля, только уже без наших гарантий.
Единственное, что мы теряем вместе с `ctx`, — бесплатный тестовый шов; поэтому шов приходится
поставлять.

**Декларативный объект: плагин экспортирует описание себя.** Всё видно без запуска. Отвергнуто не по
вкусу, а по требованию: в [vision.md](../vision.md) скил открывает агенту инструменты полем во
фронтматтере, то есть набор инструментов меняется в рантайме и одним статическим описанием не
выражается.

**И импорты, и `ctx` одновременно.** Каждый автор выбирает удобное. Отвергнуто: два способа сделать
одно и то же удваивают типы и раздваивают документацию, а в чужом плагине приходится узнавать оба.

**Шарить браузерную часть SDK как синглтон страницы.** Экономит несколько килобайт на бандл.
Отвергнуто: общий модуль не может определить, какой из плагинов его вызвал, и идентичность пришлось бы
передавать аргументом — то есть на браузерной стороне вернулся бы `ctx`, и стилей стало бы два.

## Последствия

- Вызов SDK вне воркера плагина обязан давать внятную ошибку «не инициализирован». Молчаливое
  обращение к неготовому состоянию — самый вероятный способ испортить первое впечатление автора.
- Тестовый шов становится частью публичного контракта: сломав его, мы сломаем тесты всех плагинов.
  Значит он проектируется вместе с API, а не после.
- Плагин, поднявший собственный воркер, получит там неинициализированный SDK. Это надо назвать в
  документации, потому что случай выглядит естественным, а не ошибочным.
- Прослойка дублируется в каждом браузерном бандле. Плата за одинаковый стиль, и она мала по сравнению
  с самим бандлом.
- Имена импортируемых функций становятся публичным контрактом: переименование — ломающее изменение, со
  всеми последствиями для совместимости.
