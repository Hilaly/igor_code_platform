# ADR-0050: The default agent ships as a built-in plugin

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

В базовой поставке владелец продукта запускает агента в проекте
([vision.md](../vision.md)). Инструменты этому агенту даёт рантайм
([agent-runtime-contract.md](../agent-runtime-contract.md)), но агент — не инструменты: это
настраиваемая сущность с инструкциями, набором инструментов, моделью и уровнем ризонинга.

[ADR-0047](0047-plugin-management-in-the-core-other-views-as-built-in-plugins.md) оставил ядру только
управление плагинами. Откуда берётся агент, которого пользователь запускает сразу после установки,
оставалось нерешённым.

## Решение

**Базовый агент — вклад встроенного плагина.** Ядро определений агентов не содержит.

- У этого плагина нет браузерной части: он приносит только определение агента.
- Как встроенный, он включён по умолчанию ([ADR-0019](0019-built-in-plugins-are-enabled-by-default.md)),
  живёт в `plugins/*` ([ADR-0036](0036-built-in-plugins-live-in-a-third-root-directory.md)) и объявляет
  себя манифестом в `package.json` ([ADR-0044](0044-plugin-manifest-lives-in-package-json.md)).
- Его можно перекрыть по источнику: одноимённый плагин в директории данных или в папке проекта
  побеждает встроенный. Это ровно тот сценарий, которым владелец продукта описывал источники
  плагинов — «встроенного агента можно переопределить в директории данных, а его — в конкретном
  репозитории».

**Ноль включённых агентов — законное состояние платформы.** Вклад выключается, как любой другой
([ADR-0032](0032-every-contribution-is-switchable.md)), поэтому платформа обязана внятно сказать, что
запускать нечего, а не падать при открытии вью сессий.

## Альтернативы

**Базовый агент в ядре как встроенный провайдер.** [ADR-0024](0024-ui-extends-through-named-places.md)
требует встроенного провайдера у каждого заменяемого места именно затем, чтобы выключенный плагин не
оставлял дыру, и тот же довод напрашивается для агента. Отвергнуто: у места в интерфейсе дыра
означает сломанную рамку, которую нечем нарисовать, а отсутствие агента — внятное пустое состояние
списка. Цена другая: ядро получило бы прикладное знание — инструкции и подбор инструментов, — то
есть ровно то, что ADR-0047 из него убрал.

**Аварийный агент в ядре плюс основной плагином.** Гарантия «всегда есть чем работать» без потери
заменяемости. Отвергнуто: два определения одного и того же расходятся, и первым же вопросом станет
«почему агент ведёт себя не как в плагине».

**Агент как часть плагина с вью сессий.** Одним встроенным плагином меньше. Отвергнуто: тогда
выключение интерфейса сессий уносит с собой агента, хотя это независимые вещи; и наоборот, автор,
которому нужен только свой агент, тянул бы за собой чужое вью.

## Последствия

- В поставке появляется встроенный плагин без интерфейса. Значит форма встроенного плагина не
  обязана включать браузерную часть, и это надо проверить первым же таким плагином, а не считать
  очевидным.
- Базовый агент становится первым потребителем контракта вклада «агент» — той же проверкой, какой
  встроенные вью служат для `ui-kit` ([ADR-0027](0027-ui-kit-as-a-separate-public-package.md)).
  Недостаточность контракта выяснится на нашем коде.
- Перекрытие по источнику получает рабочий пример из поставки: положить свой агент в папку проекта и
  получить его вместо встроенного можно, ничего не выключая.
- Состояние «агентов нет» придётся показывать во вью сессий и объявлять в API, потому что запуск
  сессии в этом состоянии невозможен по причине, не являющейся ошибкой.
