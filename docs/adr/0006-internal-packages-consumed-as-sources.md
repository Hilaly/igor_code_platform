# ADR-0006: Consume internal packages as TypeScript sources

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Внутренние пакеты (`protocol`, `sdk` и те, что появятся дальше) потребляются демоном и
веб-интерфейсом. Обычный для монорепы путь — собирать каждый пакет в `dist` и потреблять
результат сборки.

Рантайм исполняет TypeScript без транспайлера ([ADR-0002](0002-nodejs-lts-as-runtime.md),
проверка 1 в [runtime-checks.md](../runtime-checks.md)), поэтому сборка внутренних пакетов
перестаёт быть обязательной.

Существенно, что цикл правки для нас — не второстепенная характеристика: хот-релоад заявлен
базовой функциональностью ядра. Сборка каждого пакета означает watch-процесс на каждый пакет и
шаг между «поправил `protocol`» и «увидел в демоне».

## Решение

Внутренние пакеты потребляются исходниками. Поле `exports` указывает на `.ts`, шага сборки для
них нет.

`tsc` используется только как проверка типов (`--noEmit`), не как компилятор.

Собираются только веб-интерфейс (Vite) и продакшн-приложение целиком.

## Альтернативы

- **Каждый пакет собирается в `dist`.** Отвергнуто. Даёт привычные границы и пакет, готовый к
  публикации в любом виде, но возвращает шаг сборки в цикл разработки и требует watch на каждый
  пакет — против той самой скорости правки, ради которой строится хот-релоад.
- **Гибрид: внутри исходники, SDK собирается при публикации.** Отвергнуто. У SDK появилось бы
  два режима существования, и стало бы возможным расхождение «у нас работает, у автора плагина
  нет» — самая дорогая для отладки категория ошибок, потому что воспроизвести её у себя нельзя.

## Последствия

- Проверка типов больше не является побочным эффектом сборки. Её нужно вызывать явно —
  отдельной целью в `make` и обязательным шагом в CI. Не вызвали — типы не проверены никем.
- Пакеты, уезжающие наружу, едут исходниками. Для SDK это допустимо: его потребитель — воркер
  плагина, исполняющий TypeScript по построению ([ADR-0004](0004-plugin-typescript-execution-mode.md)).
- Vite должен резолвить `.ts` из воркспейса — проверить при создании каркаса.
- Появление потребителя, не умеющего TypeScript, делает решение непригодным и требует нового ADR.
