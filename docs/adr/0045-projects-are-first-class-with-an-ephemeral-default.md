# ADR-0045: Projects are a first-class entity with an ephemeral default project

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Владелец продукта зафиксировал предметную область ([vision.md](../vision.md)): он запускает демона,
создаёт проекты и запускает агентов в проектах. Проект описан как папка на машине, в которой он
работает.

Привязка работы агента к папке существует и в рантайме: в метаданных сессии Pi лежит рабочая
директория, а список сессий фильтруется по ней
([agent-runtime-contract.md](../agent-runtime-contract.md)). Вопрос не в том, нужна ли папка, а в
том, есть ли у платформы отдельная сущность над ней.

Рядом стоит уже принятое решение: самый частный источник плагинов — рабочая директория текущей
сессии ([vision.md](../vision.md), «Схема плагинов»). До сих пор «рабочая директория» была словом
без определения.

## Решение

**Проект — сущность первого класса: папка на машине плюс запись платформы о ней.** Сессия
принадлежит проекту. Запуска агента «просто в папке», минуя проект, платформа не предоставляет.

**Есть эфемерный проект — папка `work` внутри директории данных.** Он создаётся при первом запуске,
существует всегда и не удаляется. Это проект по умолчанию для работы, не привязанной ни к одной
папке на диске.

**Папка проекта — это и есть та рабочая директория, из которой берётся третий источник плагинов.**
Определение закрывается: плагины «из репозитория» — это плагины из папки проекта, в котором идёт
сессия.

**Папка не обязана быть репозиторием.** Никакой проверки на `.git` платформа не делает.

**Удаление проекта не удаляет папку пользователя.** Платформа удаляет свою запись; чужие файлы —
не её.

## Альтернативы

**Сессия несёт путь, сущности проекта нет.** Ровно то, что уже есть в Pi, и ноль новой работы.
Отвергнуто: владелец описал «создать проект» как отдельное действие и отдельное вью, а без сущности
негде держать ни список проектов, ни то, что к проекту прирастёт потом.

**Проект = git-репозиторий.** Дало бы бесплатно имя, ветку и историю. Отвергнуто: тогда эфемерный
проект пришлось бы превращать в репозиторий на пустом месте, а часть работы вообще не про код.

**Эфемерных проектов нет, всякая работа требует созданного проекта.** Одна сущность вместо двух
режимов. Отвергнуто владельцем продукта: проект по умолчанию нужен именно для того, чтобы начать
работать, ничего не создавая.

**Эфемерная папка вне директории данных, например во временной директории ОС.** Честнее по смыслу
слова «эфемерный». Отвергнуто: ОС чистит временные директории, а работа агента там — не мусор;
кроме того, всё состояние платформы уже собрано в одной директории
([ADR-0008](0008-data-directory-config-and-instance-lock.md)).

## Последствия

- Директория данных перестаёт быть только состоянием платформы: в ней появляются файлы, которые
  создаёт пользователь и агент. Это второй такой случай после исходников встроенных плагинов
  ([ADR-0035](0035-production-artifact-embeds-the-frontend-and-built-in-plugin-sources.md)), и
  теперь при переносе или чистке директории данных нужно понимать, что там лежит чужая работа.
- Папка проекта может исчезнуть, пока сессии в ней живы. Значит у проекта появляется состояние
  «папка недоступна», и его нужно показывать, а не падать при первом обращении.
- Эфемерный проект — часть третьего источника плагинов, то есть плагин, положенный в `work`,
  перекрывает встроенный. Это следствие, а не отдельное решение, и оно неочевидно.
- Появляется место, куда попадут будущие настройки уровня проекта. Заводить их сейчас незачем.
