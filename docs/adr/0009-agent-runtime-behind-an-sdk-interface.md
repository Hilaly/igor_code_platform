# ADR-0009: Agent runtime behind an SDK interface, Pi as the implementation

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Платформа существует ради запуска ИИ-агентов: плагины должны уметь стартовать агентные сессии,
следить за их работой и вмешиваться в неё. Писать свой агентный рантайм — отдельный продукт
размером больше самой платформы, поэтому берётся готовый: [Pi](https://github.com/earendil-works/pi).

Что он даёт, разобрано в [agent-runtime-contract.md](../agent-runtime-contract.md): цикл агента,
инструменты, дерево сессий, события с правом вето, доступ к LLM-провайдерам и их авторизации.

Развилка не в том, брать ли Pi, а в том, что видят плагины. Если они зовут Pi напрямую,
публичным контрактом платформы становится чужой API целиком, вместе с его версионированием.

## Решение

**Типы и интерфейс запуска сессии объявляются в `@sovereign/sdk`.** Плагины видят только их.

**Реализация — прикладной сервис в ядре.** Он владеет реальными объектами Pi; плагин получает
дескриптор сессии и работает через SDK.

**Код, знающий про Pi, изолирован в отдельном пакете** — `packages/agent-runtime-pi`. Ни ядро,
ни плагины не импортируют `@earendil-works/*` напрямую.

**Систему расширений Pi (`pi-coding-agent`) не используем.** Точка расширения у нас одна — наши
плагины.

**Авторизация в LLM-провайдерах берётся из Pi**: `Models.login`/`logout`/`getAuth`. Хранилище
кредов — наша реализация `CredentialStore` поверх директории данных
([ADR-0008](0008-data-directory-config-and-instance-lock.md)).

## Альтернативы

**Плагины зовут Pi напрямую.** Дешевле всего сегодня: не надо проектировать интерфейс, доступна
вся мощь их API немедленно. Отвергнуто — обновление Pi становится ломающим изменением платформы,
а SDK перестаёт быть нашим контрактом. При том что SDK — единственный пакет, который видят
посторонние, и ломать его дороже всего ([repository-structure.md](../repository-structure.md)).

**Свой агентный рантайм.** Отвергнуто: объём работы несопоставим с задачей, а список
LLM-провайдеров пришлось бы вести самим.

**Форк Pi.** Даёт полную власть над контрактом ценой вечного мержа чужих релизов. Не нужен: всё,
что мы хотели подменить — хранилище сессий и хранилище кредов, — у них и так внедряется
приложением.

## Последствия

- Наш интерфейс по форме будет повторять возможности Pi: придумать в нём то, чего Pi не умеет,
  нельзя. Это осознанная плата, а не недосмотр.
- Смена бэкенда позже возможна, но обойдётся в перенос той части контракта, которая утекла из Pi
  в форму нашего интерфейса. Полной изоляции здесь не бывает.
- Версия Pi фиксируется, а его контракт задокументирован. Обновление — отдельная задача с
  перечитыванием [agent-runtime-contract.md](../agent-runtime-contract.md), а не бампом версии.
- `@earendil-works/pi-agent-core` требует Node >= 22.19.0 — с нашей 24 совместим
  ([ADR-0002](0002-nodejs-lts-as-runtime.md)).
- Появляется правило зависимостей: импорт `@earendil-works/*` разрешён только внутри
  `packages/agent-runtime-pi`. Оно проверяется линтером так же, как граница `apps`/`packages`
  ([ADR-0005](0005-apps-and-packages-layout.md)).
