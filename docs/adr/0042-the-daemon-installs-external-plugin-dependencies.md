# ADR-0042: The daemon installs external plugin dependencies, and respects the ones brought along

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

По [vision.md](../vision.md) плагин распространяется как папка с исходниками, и ему разрешено
использовать сторонние npm-зависимости. Значит кто-то обязан их поставить, и это не пользователь
руками: включение плагина — это переключатель в интерфейсе, а не сеанс работы в терминале.

Для **встроенных** плагинов вопрос закрыт: их зависимости решаются при сборке артефакта
([ADR-0035](0035-production-artifact-embeds-the-frontend-and-built-in-plugin-sources.md)). Открытым
оставался внешний плагин — из директории данных или из рабочей директории сессии.

Отдельно стоит убрать ложный вариант: бандлить серверную часть плагина, как демон бандлит браузерную
([ADR-0025](0025-plugin-browser-code-is-built-by-the-daemon.md)), доставку не решает. Чтобы вшить
зависимость в бандл, её сначала надо получить; это шаг после доставки, а не вместо неё.

## Решение

**Если в папке плагина есть `node_modules` — демон не ставит ничего.** Работает с тем, что привезли, и
не сверяет содержимое с манифестом: привезённые модули — это осознанный выбор автора, в том числе для
работы без сети и с точными версиями.

**Если `node_modules` нет, а `package.json` есть — демон ставит зависимости в папку плагина,** вызывая
`npm` из `PATH`. Переустановка — при изменении манифеста.

**Установка — этап жизненного цикла плагина,** видимый наравне с остальными
([ADR-0018](0018-plugin-lifecycle-is-observable.md)): она публикуется событием, а её ошибка — это
состояние плагина с диагностикой, а не тихий сбой. До завершения установки плагин не считается
запущенным.

**Своего установщика не пишем.** Lock-файлы, проверка целостности, распаковка тарболлов, кеш — это
отдельный продукт, а не деталь платформы. Берём `npm`, который приходит вместе с Node
([ADR-0002](0002-nodejs-lts-as-runtime.md)). Нет `npm` в `PATH` — внятная диагностика: плагину с
зависимостями нужен либо установщик в системе, либо привезённые модули.

**`postinstall`-скрипты исполняются.** Новой границы доверия здесь не появляется: включённый плагин
доверен, и его код всё равно исполняется в воркере
([ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md)). Пугать пользователя предупреждением о
скриптах в момент, когда он уже разрешил исполнение кода, — ложная безопасность.

## Альтернативы

**Только привезённые модули, демон не ставит ничего.** Офлайн, детерминированно, ноль внешних
инструментов. Отвергнуто как единственный путь: автор обязан собрать нативные аддоны под каждую ОС и
архитектуру пользователя, обновление одной зависимости превращается в переупаковку, а «папка с
исходниками» весит десятки мегабайт. При этом как **побочный** путь этот вариант сохранён — он
достаётся бесплатно, потому что Node резолвит существующий `node_modules` сам.

**Общий `node_modules` на все плагины директории данных.** Дубли между плагинами исчезают. Отвергнуто:
два плагина с несовместимыми версиями одного пакета перестают быть совместимы друг с другом, а причина
конфликта не видна ни одному из авторов.

**Установка в отдельный каталог с дедупликацией по хешу манифеста.** Экономит диск и время, как это
делает pnpm. Отвергнуто: резолв модулей приходится подменять, чтобы плагин находил свои зависимости не
рядом с собой, — своя реализация хранилища пакетов ради экономии диска.

## Последствия

- `npm` в `PATH` становится требованием окружения для плагинов с зависимостями. Это надо назвать в
  [runbook.md](../runbook.md), иначе первым симптомом будет непонятная ошибка загрузки плагина.
- Появляется ограничение на будущее решение о формате поставки: самодостаточный бинарь, не требующий
  Node в системе, лишает демона установщика. Тогда либо установщик вшивается, либо для такой сборки
  остаётся только вариант с привезёнными модулями.
- Платформа, которая «работает локально», в момент включения плагина ходит в интернет. Осознанно: кому
  это неприемлемо — привозит `node_modules`.
- Первая загрузка плагина с зависимостями долгая, и это видно в интерфейсе именно потому, что установка
  объявлена этапом жизненного цикла, а не скрытой подготовкой.
- **Хот-релоад обязан игнорировать `node_modules` внутри папки плагина.** Наблюдение идёт за
  директорией ([runtime-checks.md](../runtime-checks.md), проверка 12), а установка пишет в ту же
  директорию тысячи файлов — без исключения этого подкаталога установка вызвала бы перезагрузку
  плагина, которая вызвала бы проверку зависимостей, и так по кругу.
