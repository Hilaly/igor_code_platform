# ADR-0055: The agent contribution declares instructions, tool selection, model, reasoning level and skills

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[ADR-0054](0054-contributions-are-registered-per-kind.md) сделал регистрацию вкладов типизированной по
видам и оставил состав полей каждого вида на отдельные решения. Первый вид, которому контракт нужен
прямо сейчас, — «агент»: базовый агент поставляется вкладом встроенного плагина
([ADR-0050](0050-the-default-agent-ships-as-a-built-in-plugin.md)), и без полей его нечем описать.

Владелец продукта описал агента так: «для агента задаются инструкции, какие инструменты брать и какие
не брать, какая модель, какой уровень ризонинга» ([vision.md](../vision.md)). Там же — про скилы:
«скил может открывать агенту инструменты», пример — у агента список `file-*`, скил добавляет
инструменты GitHub.

Рантайм всё это поддерживает и меняет на живой сессии: `systemPrompt`, `setTools` вместе с
`setActiveTools`, `setModel`, `setThinkingLevel`, `setResources`
([agent-runtime-contract.md](../agent-runtime-contract.md)).

## Решение

Вклад «агент» объявляет **пять** прикладных полей поверх общей части вклада — идентификатора и
метаданных отображения (ADR-0054):

- **инструкции** — системный промпт агента;
- **отбор инструментов** — что брать и что не брать. Отбор задаётся **шаблонами имён**, а не
  списком: набор инструментов динамический, он собирается хуком `tools_collect` из включённых
  плагинов и меняется при перезагрузке любого из них
  ([ADR-0037](0037-platform-hooks-for-session-lifecycle-veto-and-turn-accounting.md)), поэтому
  перечислить его в определении агента нельзя. Пример владельца — `file-*` — и есть шаблон;
- **модель**;
- **уровень ризонинга**;
- **скилы, доступные агенту**.

**Модель и уровень ризонинга в определении агента — значения по умолчанию, а не фиксация.** Владелец
продукта потребовал переопределять их на каждый турн, а не только при старте сессии (vision.md), и
рантайм это умеет.

**Скилы объявляются агентом, а инструменты открывает ядро.** Сам `AgentHarness.skill()` наше поле
фронтматтера не читает и `setActiveTools` не зовёт — это делаем мы (agent-runtime-contract.md).
Значит поле «скилы» у агента отвечает на вопрос «какие скилы этому агенту доступны», а расширение
набора инструментов происходит в момент загрузки скила, а не при регистрации агента.

## Альтернативы

**Ровно четыре поля из vision, без скилов.** Каждое поле обосновано словами владельца, лишнего нет.
Отвергнуто владельцем продукта. Взвешивая честно: поле всё равно появилось бы, потому что скилы в
vision открывают инструменты именно этому агенту, — только позже и ценой версии платформы
([ADR-0044](0044-plugin-manifest-lives-in-package-json.md)).

**Всё, что настраивается у harness: плюс режимы очередей стиринга и догоняющих сообщений, параметры
стрима, политика повторов.** Добавлять потом ничего не пришлось бы. Отвергнуто владельцем продукта; и
по существу эти поля описывают поведение сессии, а не свойства агента, — смешивать их в одном вкладе
значит отвечать на вопрос «чей это параметр» неверно.

**Отбор инструментов списком имён.** Проще проверить при регистрации: имя либо есть, либо нет.
Отвергнуто: набор собирается в рантайме, поэтому «проверить при регистрации» невозможно в принципе, а
список пришлось бы править при появлении каждого нового инструмента.

## Последствия

- Проверить отбор инструментов при регистрации нельзя — шаблон может не совпасть ни с чем. Значит
  «агент, у которого не осталось ни одного инструмента» — законное состояние, и его надо показывать,
  а не считать ошибкой конфигурации.
- Модель, названная агентом, может быть недоступна: провайдер не авторизован или это кастомный
  провайдер выключенного плагина ([ADR-0048](0048-plugins-get-provider-operations-not-credential-values.md)).
  Поведение в этом случае — часть того же вопроса, что исчезновение инструмента посреди сессии
  ([ADR-0015](0015-core-provides-extension-points-not-policy.md)), и решается вместе с ним.
- Определение агента — данные, а не код: плагину без браузерной части и без логики достаточно
  манифеста и регистрации. Это ровно то, чем является встроенный плагин базового агента (ADR-0050), и
  первая проверка того, что такая форма плагина работает.
- Перекрытие по источнику получает смысл на уровне поля, а не только файла: положив своего агента с
  тем же идентификатором в папку проекта, владелец меняет инструкции и отбор инструментов, ничего не
  выключая ([ADR-0030](0030-providers-resolve-by-plugin-source.md)).
