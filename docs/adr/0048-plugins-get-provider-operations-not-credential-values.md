# ADR-0048: Plugins get provider operations, not credential values

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Вью «Модели и провайдеры» поставляется встроенным плагином
([ADR-0047](0047-plugin-management-in-the-core-other-views-as-built-in-plugins.md)), значит работа с
провайдерами и авторизация в них обязаны быть в SDK. Вопрос — в форме.

Границей безопасности это не является: включённый плагин исполняется с правами процесса и читает
директорию данных сам ([ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md)). Зато есть
техническое обстоятельство из исходников Pi
([agent-runtime-contract.md](../agent-runtime-contract.md)): запись креда идёт единственным путём —
сериализованным read-modify-write, внутри которого обновляется OAuth-токен. Он существует именно для
того, чтобы параллельные запросы не обновили токен дважды.

## Решение

**SDK отдаёт операции, а не значения.** Плагин может: получить список провайдеров и моделей, узнать
статус авторизации, обновить динамический список моделей, войти, выйти, зарегистрировать свой
провайдер. Значение креда через SDK не читается и не записывается.

**Единственный писатель кредов — платформа.** Причина не в защите, а в сериализации: второй писатель
ломает обновление токена молча и редко, и симптом будет выглядеть как случайный отвал авторизации.

**Интерактивный вход — операция с каналом вопросов, а не событие шины.** Логин у Pi требует диалога:
показать ссылку, показать код устройства, спросить текст или выбор, сообщить прогресс. По шине это
делать нельзя — событие там уведомление, request-response запрещён
([ADR-0041](0041-bus-events-are-notifications-state-is-requested-from-its-owner.md)). Значит шаги
диалога — часть контракта операции входа, и типы шагов объявлены в нашем SDK, а не реэкспортированы
из Pi ([ADR-0009](0009-agent-runtime-behind-an-sdk-interface.md)).

**Доступ — у любого включённого плагина, без системы разрешений.** Это прямое следствие ADR-0016:
границей является факт включения. Отдельная модель разрешений была бы там же и отвергнута.

## Альтернативы

**Полный доступ к кредам, чтение и запись.** Честно отражает реальность — файл плагину и так
доступен. Отвергнуто по сериализации: наличие второго легального писателя означает, что обновление
OAuth-токена перестаёт быть надёжным, а отладка такого отказа стоит дорого.

**Операции плюс чтение значений.** Полезно плагину, который хочет позвать модель сам, минуя нашу
сессию. Отвергнуто: реальная потребность этим не закрывается — прямой вызов модели должен идти нашим
API, иначе на плагине оказывается вся работа с истечением токенов, повторами и учётом стоимости.

**Логин целиком в ядре, плагину только кнопка «войти».** Меньше контракта. Отвергнуто: тогда шаги
диалога рисует ядро, то есть у ядра появляется свой интерфейс входа, и вью настроек провайдеров
перестаёт быть заменяемым — это отменяет ADR-0047 для одного из пяти вью.

## Последствия

- Плагин не может позвать LLM-провайдера напрямую нашим кредом. Способ обойти есть — прочитать файл
  самому, — но это вне контракта, и на такой плагин наши гарантии не распространяются.
- Вход и выход меняют глобальное состояние, а сделать это может любой включённый плагин. Значит и
  вход, и выход обязаны публиковать событие на шину: иначе разлогин, сделанный одним плагином,
  выглядит для остальных как внезапная поломка.
- Шаги интерактивного входа становятся публичным типом SDK. Появится провайдер с принципиально
  другим способом входа — контракт придётся расширять, а это версия платформы
  ([ADR-0044](0044-plugin-manifest-lives-in-package-json.md)).
- Кастомный провайдер, зарегистрированный плагином, исчезает вместе с выключением плагина. Модель,
  выбранная в сессии из такого провайдера, окажется недоступной — поведение в этом случае надо будет
  определить там же, где поведение при исчезновении инструмента посреди сессии
  ([ADR-0015](0015-core-provides-extension-points-not-policy.md)).
