# ADR-0046: The session API covers the full runtime surface and adds archiving

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Владелец продукта назвал обязательными стиринг, форк, архив и разархивирование сессий и попросил
прочитать, что умеет агентный рантайм, чтобы его возможности стали возможностями платформы.

Прочитано по исходникам и записано в [agent-runtime-contract.md](../agent-runtime-contract.md).
Помимо ожидаемого, рантайм даёт три очереди сообщений с разными точками вклинивания, компакцию,
навигацию по дереву с суммаризацией ветки, смену модели, уровня ризонинга и набора инструментов
посреди турна, метки, имя сессии и статистику по токенам и стоимости. Архива в нём нет.

Второе обстоятельство: интерфейс поставляется плагинами, а плагин ходит в ядро только через SDK
([ADR-0043](0043-plugin-sdk-is-an-importable-module-surface.md)). Возможность, которую ядро не
отдало наружу, недоступна никому — её нельзя добавить плагином, только правкой ядра.

## Решение

**API работы с сессиями покрывает всю поверхность возможностей рантайма, а не подмножество под
первое вью.** Перечень — в [sessions-and-projects.md](../sessions-and-projects.md).

**Архив и разархивирование — наш слой.** В рантайме есть удаление и список, понятия «убрано с глаз,
но не потеряно» нет. Значит признак архивности — наши метаданные сессии, и он не переезжает в дерево
записей Pi.

**Переопределение модели и уровня ризонинга на каждый турн — не надстройка.** Рантайм пишет и то, и
другое отдельными записями дерева сессии, поэтому переопределение восстанавливается при
перечитывании и нам не нужно хранить его вторым местом.

**Одна поверхность на два потребителя.** Веб-API и SDK отдают один и тот же набор возможностей.
Разные наборы для интерфейса и для плагинов — это два контракта на одну сущность и гарантированный
рассинхрон.

## Альтернативы

**Отдать подмножество: запуск, стиринг, форк, архив.** Меньше кода и меньше публичного контракта.
Отвергнуто: «минимально возможная платформа» — про объём прикладной функциональности, а не про
объём агентного API; недоданная возможность становится правкой ядра, а весь смысл в том, чтобы
дострой шёл плагинами.

**Проксировать типы Pi наружу как есть.** Ноль работы по описанию контракта. Отвергнуто:
[ADR-0009](0009-agent-runtime-behind-an-sdk-interface.md) запрещает `@earendil-works/*` за
пределами пакета реализации, иначе замена рантайма ломает все плагины сразу.

**Считать архив просто фильтром в интерфейсе.** Ничего не хранить. Отвергнуто: тогда у каждого вью
свой список скрытого, а плагин о чужом решении не знает; архив — состояние сессии, а не настройка
отображения.

**Реализовать архив удалением с копией.** Отвергнуто как ловушка: архив обязан быть обратимым,
а восстановление из копии — это отдельный механизм со своим набором способов сломаться.

## Последствия

- Публичный контракт становится широким сразу, а не по мере надобности. Сузить его потом — ломающее
  изменение, поэтому цена ошибки в именах и форме возрастает
  ([ADR-0044](0044-plugin-manifest-lives-in-package-json.md) про версии платформы).
- Фазы рантайма протекают наружу: часть операций требует простоя сессии, часть — наоборот,
  активной работы. Состояние сессии придётся показывать в интерфейсе и объявлять в SDK, иначе
  единственным способом узнать его будет пойманная ошибка «busy».
- Замена рантайма на свой харнес перестаёт быть безболезненной: харнес обязан уметь всё
  перечисленное, включая дерево с форком и компакцию. Это осознанная плата за то, что возможности
  рантайма стали возможностями платформы.
- Архив — первое состояние сессии, которого нет в дереве Pi. Значит у сессии есть наши метаданные
  помимо их метаданных, и это место, куда будет расти остальное.
