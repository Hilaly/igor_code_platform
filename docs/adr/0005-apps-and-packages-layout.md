# ADR-0005: Split the monorepo into apps and packages

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

В репозитории живут сущности с разными потребителями: демон запускает конечный пользователь,
веб-интерфейс исполняется в браузере, SDK читает посторонний автор плагина, общие типы нужны
демону и вебу одновременно.

Сейчас пакетов четыре, ожидается порядка восьми. На таком размере граница «что запускается, а
что импортируется» перестаёт держаться в голове и должна быть видна из структуры каталогов.

Главный риск — обратные зависимости: приложение начинает импортировать из соседнего приложения,
и через полгода демон нельзя собрать без фронтенда.

## Решение

Два корневых каталога:

```
apps/
  daemon/      ядро, веб-API, CLI — то, что запускает пользователь
  web/         веб-интерфейс, React + Vite
packages/
  sdk/         публичный контракт для авторов плагинов
  protocol/    схемы и типы API, общие для демона и веба
```

Правило зависимостей: `apps` зависят от `packages`; `packages` не зависят от `apps`; между
приложениями зависимостей нет. Правило проверяется автоматически — конкретный механизм
настраивается при создании каркаса. Непроверяемое правило считается отсутствующим.

Состав пакетов будет расти; корневых каталогов остаётся два.

## Альтернативы

- **Плоский `packages/*`.** Отвергнуто. Короче пути и меньше церемоний, но все пакеты
  оказываются равны, различие «приложение или библиотека» теряется, и запрет на обратные
  зависимости не на чем основать.
- **Демон в корне репозитория.** Отвергнуто. Самый быстрый старт, но корень зарастает конфигами
  всех частей сразу, а демон перестаёт быть равноправным пакетом — вынуть его оттуда потом
  дороже всего.

## Последствия

- Пути длиннее на один уровень. На четырёх пакетах это выглядит избыточно и окупается ближе к
  восьми.
- Нужен работающий контроль направления зависимостей, иначе решение остаётся декларацией.
- Появление нового пакета — это выбор между `apps` и `packages`, то есть явный ответ на вопрос
  «его запускают или импортируют».
