# ADR-0001: Repository as long-term memory

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Разработка ведётся ИИ-агентами. У агента нет памяти между сессиями: каждая сессия начинается
с нуля и видит только то, что лежит в репозитории. Решения, принятые в чате, и причины, по
которым отвергнуты альтернативы, исчезают вместе с сессией. Через несколько итераций это
приводит к повторному прохождению тупиков и к решениям, противоречащим ранее принятым.

## Решение

Репозиторий — единственное хранилище долговременного контекста проекта.

- Процессные правила — в `CLAUDE.md`, читаются агентом в начале каждой сессии.
- Предметный контекст — в `docs/`.
- Дорогие для отката решения — в `docs/adr/`, по одному файлу на решение, без правок после
  принятия.
- Обновление документации входит в тот же коммит, что и изменение кода.

## Альтернативы

- **Внешняя база знаний (Confluence, Notion).** Отвергнуто: расходится с кодом, недоступна
  агенту без интеграции и авторизации, не версионируется вместе с изменениями.
- **Только история коммитов.** Отвергнуто: `git log` объясняет отдельные изменения, но не
  даёт текущего состояния системы и не хранит отвергнутые варианты.
- **Внешняя память агента.** Отвергнуто: привязана к конкретному инструменту и пользователю,
  не переживает смену агента и не видна остальной команде.

## Последствия

- Любое значимое обсуждение заканчивается коммитом в `docs/`, иначе считается не состоявшимся.
- Появляется постоянные накладные расходы на поддержание документации в актуальном состоянии;
  устаревший документ считается багом и правится наравне с кодом.
- Смена ИИ-агента или подключение нового участника не требует передачи контекста вручную.
