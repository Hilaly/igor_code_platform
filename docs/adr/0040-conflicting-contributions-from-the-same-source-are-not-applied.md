# ADR-0040: Conflicting contributions from the same source are not applied

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[ADR-0030](0030-providers-resolve-by-plugin-source.md) разрешает спор нескольких претендентов по
источнику плагина: рабочая директория сессии перекрывает директорию данных, та — встроенные. Случай,
когда претенденты пришли **из одного источника**, это правило не разрешает, и он висел открытым
вопросом в [ui-extension-model.md](../ui-extension-model.md).

Вопрос шире интерфейса. Ровно та же коллизия возможна у двух инструментов с одним именем, двух
агентов, двух скилов, двух цветовых схем, двух каталогов одной локали — всюду, где вклад занимает
имя или заменяемое место.

**Уточняет ADR-0030** в части случая с равным источником.

## Решение

**При равном источнике не применяется ни один из конфликтующих вкладов.** Платформа не выбирает
победителя.

- Заменяемое место показывает встроенного провайдера — то же поведение, что при выключенном или
  упавшем провайдере (уже описано в модели интерфейса).
- Имя остаётся незанятым: инструмент не попадает в набор агента, схема или каталог локали не
  применяются.
- Публикуется диагностика, перечисляющая конфликтующие вклады и плагины, которые их принесли.
- Лечится выключением одного из двух вкладов
  ([ADR-0032](0032-every-contribution-is-switchable.md)) — не плагина целиком.

Правило одно для всех видов вкладов, а не только для интерфейса. Проверка коллизий идёт по
метаданным вклада, то есть **до** активации кода: метаданные доступны до загрузки бандла, это уже
свойство модели.

## Альтернативы

**Детерминированный победитель — по id, по времени загрузки, по порядку в манифесте.** Ошибки не
бывает никогда, место всегда занято. Отвергнуто: модель интерфейса прямо запрещает, чтобы замена
следовала из совпадения маршрута, id или порядка загрузки. Победитель, выбранный сравнением строк, —
случайный по существу, и установка нового плагина молча меняла бы поведение уже работающего места.

**Спросить пользователя, какой провайдер использовать, и сохранить выбор.** Явно и предсказуемо.
Отвергнуто: это разворот ADR-0030 и текста модели, где отдельного выбора провайдера нет — пользователь
выбирает, какой плагин включён и откуда взят. Появился бы второй механизм разрешения споров рядом с
правилом источников.

**Взять первый и предупредить.** Дешевле всего в реализации. Отвергнуто: предупреждение, за которым
всё равно что-то работает, читают один раз и перестают, а поведение при этом зависит от порядка
обхода каталогов.

## Последствия

- Конфликт делает функциональность **отсутствующей**, а не деградировавшей. Для заменяемого места есть
  встроенный провайдер, а для имени инструмента — нет: агент просто не увидит инструмент. Поэтому
  диагностика обязана быть заметной в интерфейсе, а не строкой в журнале.
- Два плагина, честно предлагающих одно и то же — например два клиента к одному сервису, — не могут
  быть включены одновременно. Это осознанно: платформа не угадывает, какой из них имел в виду
  пользователь.
- Реестр вкладов обязан проверять коллизии единообразно для всех видов вкладов, а не отдельной
  проверкой на каждый вид. Это требование к форме регистрации: у вклада должны быть вид, имя или
  место и источник — иначе коллизию не вычислить.
- Правило источников из ADR-0030 применяется первым, а это — только к тому, что осталось после него.
  Второго правила перекрытия не появляется.
