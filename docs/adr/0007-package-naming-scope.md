# ADR-0007: Package naming scope @sovereign

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Пакетов ожидается около восьми. Имя SDK попадает в импорты чужого кода: его будут писать авторы
плагинов, и менять его после того, как плагины разошлись, дорого.

Проверено на 2026-07-26: пакетов `@sovereign/sdk`, `@sovereign-platform/sdk`, `sovereign-sdk` и
`sovereign-platform` в npm нет. Это не доказывает, что свободен сам скоуп: он может принадлежать
организации без публичных пакетов.

## Решение

Скоуп `@sovereign`. Пакеты именуются `@sovereign/sdk`, `@sovereign/protocol`,
`@sovereign/daemon`, `@sovereign/web`.

Пакеты, не предназначенные к публикации, помечаются `"private": true`.

## Альтернативы

- **`@sovereign-platform/*`.** Отвергнуто. Совпадает с именем проекта и реже конфликтует, но
  длиннее в каждой строке импорта, а их будут сотни.
- **Без скоупа (`sovereign-sdk`).** Отвергнуто. Ничего не нужно регистрировать, но по имени
  импорта не видно, свой пакет или сторонний, и каждое имя должно быть уникально глобально.

## Последствия

- Если при публикации скоуп окажется занят, потребуется переименование. Пока SDK не разошёлся,
  это дёшево; после — нет. Отсюда: скоуп нужно занять до первой публикации SDK, а не после.
- Публикация SDK в npm как таковая ещё не решена. Решение о скоупе принято заранее, потому что
  имя пакета проникает в код с первого дня.
