# ADR-0019: Built-in plugins are enabled by default

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[ADR-0018](0018-plugin-lifecycle-is-observable.md) установил, что впервые обнаруженный плагин
выключен, и оставил открытым, распространяется ли это правило на встроенные плагины — те, что
вшиты в приложение и поставляются вместе с ним.

Правило «выключен по умолчанию» защищает от кода, который пользователь не выбирал. Встроенные
плагины он выбрал в тот момент, когда установил платформу: их поставили мы, тем же артефактом,
что и ядро.

## Решение

**Встроенные плагины включены по умолчанию.** Правило «новый плагин выключен» относится к
плагинам из директории данных и из рабочей директории сессии.

Выключить встроенный плагин пользователь по-прежнему может — настройка «включён / выключен» есть
у каждого плагина ([ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md)).

## Альтернативы

**Выключены, как и все остальные.** Формально последовательнее, но делает свежую установку
мёртвой: платформа не умеет ничего, пока пользователь не найдёт и не включит поставленное вместе
с ней. Защиты это не добавляет — согласие на встроенный код уже дано установкой.

## Последствия

- Граница доверия из ADR-0016 получает исключение: код, поставленный нами, исполняется без
  отдельного подтверждения. Значит встроенный плагин — часть поставки и отвечаем за него мы, а
  не пользователь. Требование к отбору: во встроенные попадает только то, что мы готовы включать
  всем по умолчанию.
- Обновление приложения может привнести новый встроенный плагин, который сразу включится. Это
  нормально для нашего кода, но означает, что список встроенных — часть release notes, а не
  деталь реализации.
- Переопределённый встроенный плагин (тот же плагин из директории данных или репозитория —
  [vision.md](../vision.md)) наследует не состояние встроенного, а правило своего источника:
  перекрывающая версия — новый, ранее не виданный код, и она выключена. Иначе подмена
  встроенного плагина обходила бы согласие пользователя.
