# ADR-0018: Plugin lifecycle is an observable event stream; new plugins start disabled

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md) сделал включение плагина границей
доверия, но оставил открытым, в каком состоянии оказывается впервые обнаруженный плагин.

Второй вопрос — кто вообще узнаёт о том, что с плагинами происходит. Плагины загружаются,
выгружаются, падают и перезапускаются на живой системе; интерфейс должен это показывать, а другие
плагины — иметь возможность отреагировать.

## Решение

**Впервые обнаруженный плагин выключен.** Чтобы код заработал, пользователь должен включить его
сам — иначе граница доверия из ADR-0016 не значила бы ничего.

**Жизненный цикл плагина публикуется доменными событиями в шину**
([ADR-0012](0012-global-event-bus.md)): обнаружен, запускается, запущен и далее по состояниям.
События получают и веб-интерфейс, и другие плагины: интерфейс обновляется, плагины реагируют.

## Альтернативы

**Новый плагин включён по умолчанию.** Удобнее: положил папку — заработало. Отвергнуто:
недоверенный код исполнялся бы без единого вопроса, а весь механизм защиты сводился бы к тому,
успел ли пользователь заметить новую папку.

**Состояние плагинов только через запрос к API.** Интерфейс узнавал бы об изменениях с задержкой
или через поллинг, который запрещён ([ADR-0013](0013-sse-for-server-initiated-updates.md)).

## Последствия

- Полного перечня состояний в решении нет — названы обнаружен, запускается, запущен. Остальные
  (выгружается, выгружен, упал, перезапускается) появятся вместе с реализацией супервизора.
- Событий недостаточно: вкладка, открытая позже, пропустила всё, что было до неё. Значит нужен
  разовый запрос за текущим снимком состояний плюс поток изменений. Это общий шаблон для всего
  интерфейса, а не особенность плагинов.
- Открыто: касается ли «выключен по умолчанию» встроенных плагинов. Если да, свежая установка
  ничего не делает, пока пользователь не включит поставленное вместе с приложением.
- Открыто: нужны ли на переходы жизненного цикла ещё и хуки с правом вмешаться, а не только
  события-факты. Владелец продукта в этом не уверен, и без реального сценария решать нечего.
