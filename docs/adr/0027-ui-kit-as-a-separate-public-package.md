# ADR-0027: UI kit as a separate public package

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Браузерный UI плагина исполняется компонентом в realm хоста
([ADR-0023](0023-single-renderer-tier-for-plugin-ui.md)) и стоит рядом с нашими элементами — иногда
вместо них ([ADR-0024](0024-ui-extends-through-named-places.md)). Значит плагину нужны те же
примитивы, из которых сделан наш интерфейс. Иначе каждый плагин приносит свой набор кнопок и полей,
и интерфейс расползается на глазах, хотя формально всё работает.

Владелец продукта зафиксировал: UI-кит пишется до начала прикладной разработки и становится частью
SDK, но отдельным пакетом.

## Решение

**`packages/ui-kit` — публичный пакет, отдельный от `packages/sdk`.**

- Наш веб-интерфейс строит оболочку и встроенные компоненты **только** из кита.
- Кит не импортирует `apps/*` — он ничего не знает о приложении, которое его использует.
- Кит пишется раньше прикладного кода.

**Отдельный пакет, а не часть `sdk`,** потому что у них разные зависимости: `sdk` — это контракты и
типы, он не должен тянуть React; кит тянет React и стили. Плагин без браузерной части подключает
только `sdk`.

## Альтернативы

**Примитивы внутри `sdk`.** Один пакет вместо двух. Отвергнуто: любой плагин, даже без интерфейса,
получал бы React в зависимостях.

**Плагины используют что угодно.** Максимум свободы автору. Отвергнуто: интерфейс перестаёт быть
одним продуктом, а темы не работают вовсе — компонент со своим цветом не переключится вместе с
цветовой схемой ([ADR-0028](0028-themes-color-schemes-and-localization.md)).

**Взять внешнюю библиотеку компонентов и объявить контрактом её.** Меньше работы сейчас. Отвергнуто:
наш публичный контракт оказался бы привязан к чужому релизному циклу, и его ломающие изменения
становились бы нашими. Использовать внешнюю библиотеку **внутри** кита это решение не запрещает.

## Последствия

- Кит — публичный контракт, наравне с SDK. Ломать его дороже, чем что-либо в приложении.
- Наш собственный интерфейс обязан пользоваться только китом. Компонент, сделанный «на месте» в
  `apps/web`, немедленно становится тем, что плагин воспроизвести не может, — это регресс контракта,
  а не локальное удобство.
- Кит тянет React, а версия React уже часть публичного контракта
  ([ADR-0025](0025-plugin-browser-code-is-built-by-the-daemon.md)). Теперь у этого есть второе
  место проявления: мажорное обновление React — ломающий релиз и кита.
- Первые недели работы дают не функциональность, а фундамент. Принято владельцем продукта
  сознательно: кит, дописываемый после прикладного кода, всегда отстаёт от него и превращается в
  свалку вынесенных постфактум компонентов.
