# ADR-0030: Providers resolve by plugin source specificity

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[ADR-0024](0024-ui-extends-through-named-places.md) ввёл заменяемые места, но не сказал, как
выбирается активный провайдер, если претендентов несколько. Исходный набросок предлагал явный выбор
пользователя на каждое место, с сохранением предпочтения и поведением при исчезновении провайдера.

У плагинов правило перекрытия уже есть и оно другое: три источника — встроенные, директория данных,
рабочая директория сессии, — и побеждает более частный ([vision.md](../vision.md)).

Владелец продукта решил: у провайдеров то же правило, что у остального.

## Решение

**Активный провайдер заменяемого места выбирается по источнику плагина:** рабочая директория
перекрывает директорию данных, та — встроенный.

Отдельного пользовательского выбора провайдера для места нет. Выбор пользователь делает раньше и
крупнее: он решает, какой плагин включён и из какого источника тот приходит
([ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md)).

**Не решено:** что происходит, когда на одно место претендуют два разных плагина **из одного
источника**. Правило источников этот случай не разрешает. Предложение агента, не утверждено: явная
запись в `config.json`, а без неё — встроенный провайдер и диагностика, то есть платформа не
угадывает.

## Альтернативы

**Явный выбор пользователя на каждое место.** Гибче и позволяет включить плагин, оставив встроенный
внешний вид. Отвергнуто: это второе правило перекрытия рядом с первым, плюс интерфейс выбора,
хранение предпочтений и семантика «выбранный провайдер исчез» — механика ради решения, которое
пользователь уже принял, когда включил плагин.

**Порядок регистрации.** Ничего не требует. Отвергнуто: зависит от таймингов загрузки, то есть
невоспроизводимо и необъяснимо пользователю.

## Последствия

- Правило перекрытия на платформе одно — и для файлов плагина, и для провайдеров мест. Меньше
  объяснений и меньше расхождений между разделами документации.
- Положить плагин в репозиторий — значит осознанно перекрыть глобальный. Это удобно ровно там, где
  задумано: особый вид интерфейса под конкретный проект.
- Обратная сторона: нельзя «включить плагин, но оставить встроенный компонент». Единственный способ —
  выключить плагин или убрать его из более частного источника. Принято ради простоты правила.
- Выбор не переживает перемещения плагина: переложили папку в другой источник — изменился приоритет.
  Это ожидаемо для правила, основанного на источнике, но означает, что источник плагина должен быть
  виден в интерфейсе управления плагинами.
