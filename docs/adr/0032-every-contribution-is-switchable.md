# ADR-0032: Every plugin contribution can be switched off individually

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

[ADR-0030](0030-providers-resolve-by-plugin-source.md) выбрал одно правило перекрытия — по источнику
плагина — и заплатил названной ценой: нельзя оставить встроенный компонент, не выключив плагин
целиком. Тот же ADR оставил открытым случай двух плагинов из одного источника, претендующих на одно
место.

Владелец продукта расширил решение с интерфейса на всю платформу: переключается не только плагин, а
**любой его вклад** — инструмент, скил, агент, подписка на хук, компонент интерфейса, цветовая схема,
каталог локали.

## Решение

**Единица переключения — вклад,** под тем же устойчивым идентификатором, под которым плагин его
зарегистрировал ([ADR-0024](0024-ui-extends-through-named-places.md)).

**Выключенный вклад не участвует ни в чём:** ни в разрешении провайдеров заменяемых мест, ни в
сборке динамических списков — инструментов, схем, локалей, подписок на хуки. Правило источников
применяется к тому, что осталось. **Второго правила перекрытия не появляется:** это фильтр до
разрешения, такой же, как включённость самого плагина.

**Вклад включённого плагина по умолчанию включён.** Это не противоречит
[ADR-0018](0018-plugin-lifecycle-is-observable.md) и
[ADR-0019](0019-built-in-plugins-are-enabled-by-default.md): там речь о доверии к незнакомому коду,
здесь — о вкусе и о конфликтах. Доверие уже дано включением плагина, а требовать включать каждый
новый инструмент после обновления плагина — превращать обновление в квест.

**Выключенные вклады перечисляются в `config.json`** парой «плагин и идентификатор вклада»
([ADR-0020](0020-files-for-human-state-sqlite-for-machine-state.md)). Запись сохраняется, даже если
вклад исчез: вернулся — остаётся выключенным. Чистится при удалении плагина.

**Эффект немедленный.** Списки пересобираются; активная цветовая схема падает на схему по умолчанию;
выключенный каталог локали — на базовую локаль; заменяемое место — на встроенный провайдер.

**Выключение вклада не является мерой безопасности.** Код плагина продолжает работать в своём
воркере. Границей доверия остаётся включение плагина
([ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md)).

## Альтернативы

**Переключать только плагин целиком** — как было. Не даёт оставить встроенный компонент и оставляет
конфликт двух плагинов из одного источника без выхода.

**Отдельный выбор провайдера для каждого заменяемого места.** Отвергнуто в ADR-0030 и здесь не
возвращается: фильтр «этот вклад не участвует» — не то же, что второе правило «для этого места
я выбираю вот того».

**Переключать по типу вклада** (все инструменты плагина сразу). Грубее, чем нужно, и не решает
случай двух плагинов, дающих по навигатору.

**Новый вклад выключен по умолчанию.** Последовательно с правилом для новых плагинов. Отвергнуто:
обновление плагина перестаёт работать до ручного вмешательства, а защиты это не добавляет — код
плагина всё равно исполняется.

## Последствия

- Плагин можно привести в состояние, которое автор не тестировал: часть его вкладов выключена.
  Отсюда обязанность, которую надо записать в контракт SDK: **плагин не вправе считать, что все его
  вклады активны.** Отсутствие своего же инструмента — нормальное состояние, а не ошибка.
- Интерфейс управления плагинами обязан показывать состав вкладов и источник плагина. Без этого
  переключатели негде нажимать, а приоритет провайдеров необъясним.
- Выключение инструмента во время работы агента ложится на уже существующий механизм: список
  инструментов объявлен динамическим ([ADR-0015](0015-core-provides-extension-points-not-policy.md)),
  а Pi поддерживает смену набора посреди турна — новый набор применяется со следующего запроса
  ([agent-runtime-contract.md](../agent-runtime-contract.md)).
- Сессия, начатая вкладом, который затем выключили, продолжает работать — как и при выгрузке плагина
  ([ADR-0010](0010-core-owns-agent-sessions.md)).
- Открытый вопрос про двух претендентов из одного источника перестаёт быть тупиком: платформа
  по-прежнему не угадывает, но у пользователя есть действие — выключить один из двух вкладов.
- `config.json` растёт списком выключенного. Это состояние пользователя, оно переносится вместе с
  директорией данных, и это уже обеспечено ADR-0008.
