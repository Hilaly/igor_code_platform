# ADR-0025: The daemon builds plugin browser code and shares its React instance

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Плагины распространяются исходниками: одна папка, внутри TypeScript ([vision.md](../vision.md)).
Браузерная часть плагина исполняется доверенным компонентом в realm хоста
([ADR-0023](0023-single-renderer-tier-for-plugin-ui.md)), то есть внутри нашего
React-приложения.

Отсюда жёсткое техническое ограничение, а не предпочтение: **React-хуки работают только при одном
экземпляре React на страницу.** Плагин, притащивший свою копию React, получит сломанные хуки и
пустой контекст — не в редком случае, а сразу.

Второе ограничение: браузер не исполняет TypeScript и TSX. Кто-то должен превратить исходники
плагина в модули, которые браузер загрузит, и делать это заново при каждой правке — хот-релоад
объявлен базовой функциональностью ядра.

## Решение

**Браузерные исходники плагина собирает демон.** Автор плагина шага сборки не имеет: он кладёт
папку с исходниками, всё остальное делает платформа.

**Результат отдаётся по URL, содержащему ревизию** сборки. Ассеты ревизии неизменяемы и кешируются
браузером бессрочно; новая правка плагина — это новая ревизия и новый URL, а не сброс кеша.

**Singleton-зависимости хоста в бандл плагина не собираются.** `react`, `react-dom` и остальные
общие для приложения библиотеки помечаются внешними и резолвятся в экземпляр хоста. Внутренности
`apps/web` плагину недоступны — он получает публичные сервисы SDK.

**Перезагрузка плагина — это новая ревизия плюс подмена снимка реестра вкладов**
([ADR-0024](0024-ui-extends-through-named-places.md)), без перезагрузки страницы.

## Альтернативы

**Плагин приносит собранный бандл.** Снимает с нас сборщик целиком. Отвергнуто: противоречит
поставке исходниками и требует от автора плагина настроенного окружения сборки — то есть превращает
«положил папку» в «настроил проект».

**Плагин тянет свой React.** Автономность бандла и никакой связи версий. Отвергнуто по факту:
хуки перестают работать, в памяти две копии библиотеки, контексты хоста плагину не видны.

**Отдавать исходники браузеру без трансформации.** Браузер не понимает TS/TSX, а import map на
каждый файл лишает нас контроля над кешированием и превращает загрузку плагина в сотни запросов.

**Собирать плагины в момент установки, а не в демоне.** Убирает сборщик из горячего пути.
Отвергнуто: хот-релоад по правке файла всё равно требует сборки на живой системе, то есть сборщик
в демоне нужен независимо, и второй путь сборки — лишняя сущность.

## Последствия

- Демон получает зависимость-сборщик. В воркспейсе esbuild уже разрешён к установке ради Vite, но
  для ядра это отдельное обоснование, а не автоматическое следствие.
- **Версия React становится частью публичного контракта SDK.** Обновление мажорной версии — это
  ломающее изменение для всех плагинов с браузерной частью, и оно должно объявляться как таковое.
- Старый ES-модуль после перезагрузки плагина остаётся в памяти браузера: выгрузить модуль из кеша
  браузера нельзя. Хост снимает регистрации, размонтирует деревья и вызывает освобождение ресурсов,
  но код предыдущей ревизии живёт до перезагрузки страницы. Значит число накопленных ревизий надо
  ограничивать и предлагать перезагрузку.
- Ассеты плагинов идут с того же origin, что и API: после отказа от изолированных iframe второй
  origin не нужен. Плата — они делят с SSE-соединением пул из шести соединений на источник
  ([runtime-checks.md](../runtime-checks.md), проверка 9). Это запросы, а не потоки, поэтому
  соединение занимается на время загрузки, но следить за этим придётся.
- Сборка чужого кода происходит в процессе демона. Ошибка сборки обязана быть событием жизненного
  цикла плагина, а не исключением в логе: для пользователя это единственный признак, что плагин не
  заработал.
