# ADR-0047: Plugin management lives in the core, every other view is a built-in plugin

- **Статус:** Accepted
- **Дата:** 2026-07-26

## Контекст

Владелец продукта перечислил пять вью базовой поставки — проекты, агенты и сессии, плагины,
настройки, модели и провайдеры ([vision.md](../vision.md)) — и одновременно потребовал, чтобы
платформа была минимально возможной, а всё прикладное жило в плагинах. Кто поставляет эти вью,
оставалось нерешённым.

Крайние варианты плохи по-разному. Всё в ядре — первый же собственный список сессий требует правки
ядра, то есть ровно того, чего вся затея избегает. Всё плагинами — управление плагинами становится
плагином, который можно выключить, и включить обратно будет нечем.

## Решение

**Управление плагинами — часть ядра.** Список плагинов, включение и выключение плагина и его вкладов
не могут зависеть от плагина: это единственный путь восстановления системы, и он обязан работать,
когда всё остальное выключено или упало.

**Остальные вью поставляются встроенными плагинами настолько, насколько это возможно.** Если какое-то
вью встроенным плагином быть не может, это отдельное решение с названной причиной, а не молчаливый
переезд в ядро.

Отсюда следует правило, которое сильнее любого списка API:

**SDK обязан покрывать то, что нужно встроенным вью.** Вью, поставляемое плагином, умеет ровно то,
что есть в SDK. Значит в публичный контракт попадают проекты (список, создание, удаление), сессии
([ADR-0046](0046-session-api-covers-the-full-runtime-surface-plus-archive.md)), настройки платформы,
провайдеры и модели с их авторизацией. Темы и локали уже там
([ADR-0028](0028-themes-color-schemes-and-localization.md)).

**Поставка — первый потребитель SDK.** Достаточность контракта проверяется нашими собственными вью, а
не отзывом первого внешнего автора.

Оболочка при этом остаётся ядру и заменяемой не становится
([ADR-0029](0029-the-shell-is-not-replaceable.md)): встроенное вью — вклад в именованное место, а не
своя рамка.

## Альтернативы

**Все пять вью — встроенные плагины, ядро без интерфейса.** Максимально честно к принципу
микроядра. Отвергнуто по невосстановимому состоянию: выключенное управление плагинами включить
нечем. Технически можно было бы запретить выключать конкретный плагин, но это исключение из
[ADR-0032](0032-every-contribution-is-switchable.md), то есть та же особая сущность, только
спрятанная.

**Все пять в ядре, плагины только дополняют.** Дешевле всего в реализации: никакого API наружу не
нужно. Отвергнуто владельцем продукта — и по существу: своё вью сессий тогда невозможно без правки
ядра, а SDK остался бы непроверенным до первого внешнего плагина.

**Управление плагинами в ядре, остальное в ядре тоже, но с точками расширения.** Промежуточный
вариант: вью наши, плагин добавляет к ним элементы. Отвергнуто: «добавить кнопку» и «заменить вью
своим» — разные права, а владелец хочет второе.

## Последствия

- Публичный контракт SDK расширяется сразу и заметно: настройки, проекты, провайдеры. Ломать его
  дороже, чем ядро, — это то, что уже сказано про SDK в
  [repository-structure.md](../repository-structure.md), но теперь под это попадают вещи, которые
  раньше выглядели внутренними.
- Открытие API провайдеров не создаёт новой границы безопасности: включённый плагин и так читает
  директорию данных ([ADR-0016](0016-plugin-enablement-as-the-trust-boundary.md)). Форма этого API —
  отдельное решение, а не следствие.
- Часть базовых вью можно выключить. Значит у каждого заменяемого места обязан быть встроенный
  провайдер или внятная заглушка, иначе выключенный плагин настроек оставит платформу без настроек
  ([ADR-0024](0024-ui-extends-through-named-places.md) это уже требует).
- Встроенные вью станут самым большим потребителем `ui-kit`: компонент, сделанный мимо кита, им
  недоступен так же, как внешнему плагину
  ([ADR-0027](0027-ui-kit-as-a-separate-public-package.md)). Это ровно та проверка кита, которую
  иначе пришлось бы выдумывать.
- Требование «редактировать настройки платформы» из вью, которое является плагином, упирается в
  [ADR-0033](0033-config-and-preferences-are-separate-hot-reloaded-files.md): там `config.json`
  пишет человек, а платформа только читает. Это противоречие придётся разрешить отдельным решением.
