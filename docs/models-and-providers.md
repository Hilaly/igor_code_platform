# Модели и провайдеры

Как платформа входит в LLM-провайдеров и что из этого видит плагин. Что даёт рантайм — в
[agent-runtime-contract.md](agent-runtime-contract.md), раздел «Авторизация в LLM-провайдерах».

Реализовано: `packages/agent-runtime-pi` (граница Pi), `apps/daemon/src/credential-store.ts`
(единственный писатель кредов), маршруты провайдеров и входа ([web-api.md](web-api.md)), вью
провайдеров с интерактивным входом ([ui-kit.md](ui-kit.md), раздел «Вью провайдеров») и поверхность
SDK для плагинов (`packages/sdk/src/providers.ts`, мост — `apps/daemon/src/plugin-providers.ts`).

## Механизм берётся из Pi, хранилище — наше

Логин оркестрирует приложение: `Models.login`, `logout`, `getAuth`, `checkAuth`. Хранилище кредов у
Pi внедряется, по умолчанию оно вообще in-memory, поэтому креды лежат в нашей директории данных
([data-directory.md](data-directory.md)), а не в `~/.pi/agent/`.

Запись креда идёт единственным путём — сериализованным read-modify-write, внутри которого Pi
обновляет OAuth-токен. Он существует именно для того, чтобы параллельные запросы не обновили токен
дважды.

Список провайдеров, моделей и их авторизации тоже готовый: `getProviders`, `getModels`, `refresh`,
`checkAuth`, `getAvailable`. В комплекте около сорока провайдеров, и кастомный провайдер собирается
фабрикой `createProvider` — своего механизма нам не потребуется.

## Что видит плагин

**SDK отдаёт операции, а не значения.** Плагин может: получить список провайдеров и моделей, узнать
статус авторизации, обновить динамический список моделей, войти, выйти, зарегистрировать свой
провайдер. Значение креда через SDK не читается и не записывается.

```ts
import { providers } from "@sovereign/sdk";

const list = await providers.list(); // ProviderSummary[]: статус авторизации, но не кред
const models = await providers.models("anthropic"); // undefined — такого провайдера нет
const status = await providers.status("anthropic"); // configured | unconfigured | unknown
const report = await providers.refresh(); // динамические списки моделей, все разом
```

**Каталог у плагина и у человека один.** Мост в демоне держит тот же `ProviderCatalogue`, что и
маршруты `/api/providers`: второй экземпляр означал бы вторую коллекцию провайдеров, и
зарегистрированное плагином не было бы видно во вью.

**Обновление списков публикует `core.providers.changed`** — ровно как маршрут обновления: это
глобальное состояние, и сделавший его плагин обязан быть виден остальным
([event-bus.md](event-bus.md)).

**Ошибка операции приходит исключением на месте вызова,** а не молчаливым `undefined`: причина
называется словами платформы. Пустой результат отличается от «нет такого провайдера» — у моделей и
статуса это `undefined`, а не пустой список.

**Единственный писатель кредов — платформа.** Причина не в защите, а в сериализации: второй писатель
ломает обновление токена молча и редко, и симптом выглядит как случайный отвал авторизации.

**Интерактивный вход — операция с каналом вопросов, а не событие шины.** Логин у Pi требует диалога:
показать ссылку, показать код устройства, спросить текст или выбор, сообщить прогресс. По шине это
делать нельзя — событие там уведомление, запрос-ответ запрещён ([event-bus.md](event-bus.md)). Значит
шаги диалога — часть контракта операции входа, и типы шагов объявлены в нашем SDK, а не
реэкспортированы из Pi.

**Доступ — у любого включённого плагина, без системы разрешений.** Границей является факт включения
([plugins.md](plugins.md)); отдельная модель разрешений была бы там же и отвергнута.

**Вход и выход публикуют событие на шину.** Они меняют глобальное состояние, а сделать это может
любой включённый плагин: иначе разлогин, сделанный одним плагином, выглядит для остальных как
внезапная поломка.

## Почему так

**Полный доступ к кредам, чтение и запись.** Честно отражает реальность — файл плагину и так
доступен. Отвергнуто по сериализации: наличие второго легального писателя означает, что обновление
OAuth-токена перестаёт быть надёжным, а отладка такого отказа стоит дорого.

**Операции плюс чтение значений.** Полезно плагину, который хочет позвать модель сам, минуя нашу
сессию. Отвергнуто: реальная потребность этим не закрывается — прямой вызов модели должен идти нашим
API, иначе на плагине оказывается вся работа с истечением токенов, повторами и учётом стоимости.

**Логин целиком в ядре, плагину только кнопка «войти».** Меньше контракта. Отвергнуто: тогда шаги
диалога рисует ядро, у ядра появляется свой интерфейс входа, и вью провайдеров перестаёт быть
заменяемым.

**Реэкспорт типов протокола из SDK вместо своей копии.** Одно объявление вместо двух, разойтись
нечему. Отвергнуто: SDK ставится внешним плагином из своей папки и внутренних пакетов тянуть не
должен — иначе публикуемая поверхность утаскивает за собой весь `@sovereign/protocol`. Тот же довод
уже решил судьбу `PluginLogLevel` ([plugins.md](plugins.md)).

Цена копии — молчаливое расхождение, поэтому оно **ловится компилятором в мосте демона**
(`apps/daemon/src/plugin-providers.ts`): там на каждый скопированный тип стоит присваивание в обе
стороны, и разъехавшиеся объявления перестают компилироваться. Проверка стоит именно в мосте, потому
что мост — единственное место в системе, где оба объявления видны одновременно.

Цена и следствия:

- плагин не может позвать LLM-провайдера напрямую нашим кредом. Способ обойти есть — прочитать файл
  самому, — но это вне контракта, и наши гарантии на такой плагин не распространяются;
- шаги интерактивного входа становятся публичным типом SDK. Появится провайдер с принципиально другим
  способом входа — контракт придётся расширять, а это версия платформы
  ([public-contract.md](public-contract.md));
- кастомный провайдер, зарегистрированный плагином, исчезает вместе с выключением плагина. Модель,
  выбранная в сессии из такого провайдера, окажется недоступной — что происходит дальше, описано в
  [sessions-and-projects.md](sessions-and-projects.md): сессия доигрывает с тем, что осталось.
