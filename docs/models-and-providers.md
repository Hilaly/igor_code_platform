# Модели и провайдеры

Как платформа входит в LLM-провайдеров и что из этого видит плагин. Что даёт рантайм — в
[agent-runtime-contract.md](agent-runtime-contract.md), раздел «Авторизация в LLM-провайдерах».

Реализовано: `packages/agent-runtime-pi` (граница Pi), `apps/daemon/src/credential-store.ts`
(единственный писатель кредов), маршруты провайдеров и входа ([web-api.md](web-api.md)), вью
провайдеров с интерактивным входом ([ui-kit.md](ui-kit.md), раздел «Вью провайдеров») и поверхность
SDK для плагинов (`packages/sdk/src/providers.ts`, мост — `apps/daemon/src/plugin-providers.ts`).

## Механизм берётся из Pi, хранилище — наше

Логин оркестрирует приложение: `Models.login`, `logout`, `getAuth`, `checkAuth`. Хранилище кредов у
Pi внедряется, по умолчанию оно вообще in-memory, поэтому креды лежат в нашей директории данных
([data-directory.md](data-directory.md)), а не в `~/.pi/agent/`.

Запись креда идёт единственным путём — сериализованным read-modify-write, внутри которого Pi
обновляет OAuth-токен. Он существует именно для того, чтобы параллельные запросы не обновили токен
дважды.

Список провайдеров, моделей и их авторизации тоже готовый: `getProviders`, `getModels`, `refresh`,
`checkAuth`, `getAvailable`. В комплекте около сорока провайдеров, и кастомный провайдер собирается
фабрикой `createProvider` — своего механизма нам не потребуется.

## Что видит плагин

**SDK отдаёт операции, а не значения.** Плагин может: получить список провайдеров и моделей, узнать
статус авторизации, обновить динамический список моделей, войти, выйти, зарегистрировать свой
провайдер. Значение креда через SDK не читается и не записывается.

```ts
import { providers } from "@sovereign/sdk";

const list = await providers.list(); // ProviderSummary[]: статус авторизации, но не кред
const models = await providers.models("anthropic"); // undefined — такого провайдера нет
const status = await providers.status("anthropic"); // configured | unconfigured | unknown
const report = await providers.refresh(); // динамические списки моделей, все разом
```

**Каталог у плагина и у человека один.** Мост в демоне держит тот же `ProviderCatalogue`, что и
маршруты `/api/providers`: второй экземпляр означал бы вторую коллекцию провайдеров, и
зарегистрированное плагином не было бы видно во вью.

**Обновление списков публикует `core.providers.changed`** — ровно как маршрут обновления: это
глобальное состояние, и сделавший его плагин обязан быть виден остальным
([event-bus.md](event-bus.md)).

**Ошибка операции приходит исключением на месте вызова,** а не молчаливым `undefined`: причина
называется словами платформы. Пустой результат отличается от «нет такого провайдера» — у моделей и
статуса это `undefined`, а не пустой список.

### Вход и выход

Плагин ведёт интерактивный вход целиком, своим диалогом:

```ts
const conclusion = await providers.login({
  providerId: "anthropic",
  method: "api_key",
  dialogue: {
    tell: (notice) => {}, // сообщение по ходу: ссылка, код устройства, прогресс
    ask: (prompt) => "sk-…", // вопрос: ответ возвращается сюда же
  },
});

await providers.logout("anthropic");
```

- **Шаги — часть контракта самой операции.** Они ключуются идентификатором вызова `login`, а не
  отдельным потоком: у вопроса обязан быть тот же адресат, что у вызова, иначе у одного вопроса
  оказалось бы два отвечающих. Конец диалога — не шаг, а **возвращаемое значение**: у одного
  результата не бывает двух мест.
- **Отказ ответить отменяет вход.** Обещание `ask`, отклонённое плагином, гасит попытку целиком, и
  вход кончается `cancelled`, а не `failed`: причина известна, и это не поломка провайдера.
- **Шаги попытки плагина в SSE-поток не попадают.** Они едут в его воркер и никуда больше; в снимке
  `GET /api/provider-logins` попытка при этом видна, с `answerable: false` — человек должен понимать,
  почему провайдер занят ([web-api.md](web-api.md)).
- **В одного провайдера входят по одному.** Пока идёт чужая попытка — человека или другого плагина,
  — вызов отказывается ошибкой и не отменяет её: автоотмена убивала бы наполовину пройденный диалог.
- **Выгрузка плагина посреди входа освобождает провайдера.** Владелец попытки — ключ плагина, и
  гасится она там же, где снимаются его вклады и подписки: мёртвый воркер не имеет права держать
  провайдера занятым до перезапуска демона.
- **Поверх негодного файла кредов вход не начинается** — ровно как в маршруте: диалог, который
  заведомо не сможет сохранить результат, тратит время впустую.
- **Вход и выход публикуют `core.provider.login` и `core.provider.logout`,** кто бы их ни сделал.

### Свой провайдер

```ts
await providers.register({
  id: "vendor-local",
  name: "Vendor Local",
  baseUrl: "http://127.0.0.1:11434/v1",
  api: "openai-completions", // протокол API из закрытого перечня
  apiKey: { label: "Vendor key", environmentVariables: ["VENDOR_API_KEY"] },
  models: [{ id: "vendor-large", name: "Vendor Large", contextWindow: 32_000, maxTokens: 4_096 }],
});

await providers.unregister("vendor-local"); // раньше выгрузки, если он больше не нужен
```

**Определение — только данные.** Ни функции запроса, ни своего способа входа плагин не приносит:
определение едет через границу воркера, а она — структурное клонирование, и функция её не переживает.
Отсюда пределы:

- **протокол API берётся из закрытого перечня** — `openai-completions`, `openai-responses`,
  `anthropic-messages`, `google-generative-ai`. Реализацию даёт рантайм, и на незнакомое имя ему
  нечем ответить;
- **способ авторизации один — ключ**: подпись и переменные окружения. OAuth своим провайдером не
  объявить, потому что OAuth это код;
- **цены кеша у модели нет**, только вход и выход за миллион токенов: в описании модели платформы
  ступеней и кеша нет вовсе;
- **список моделей статический.** Динамический требовал бы функции обновления.

**Занятый идентификатор — отказ операции, а не замена.** У рантайма регистрация перезаписывает
провайдера по `id`, и встроенный подменился бы молча; отказ приходит исключением с названным
идентификатором. Освобождённый идентификатор снова свободен: занятость — про живого провайдера, а не
про имя.

**Провайдер живёт, пока жив плагин.** Демон помнит, чей он, и убирает его при выгрузке, падении и
перезагрузке — там же, где снимает вклады и подписки; вернувшийся плагин регистрируется заново в
`activate`, та же механика, что у подписок на шину. Оба перехода публикуют `core.providers.changed`.
Убрать чужой провайдер нельзя — убирается только своё.

**Кред кастомного провайдера лежит в общем `credentials.json` и переживает плагин.** Хранилище
кредов ключуется идентификатором провайдера и о плагинах не знает: снятый и заново
зарегистрированный провайдер оказывается настроенным сразу.

**Единственный писатель кредов — платформа.** Причина не в защите, а в сериализации: второй писатель
ломает обновление токена молча и редко, и симптом выглядит как случайный отвал авторизации.

**Интерактивный вход — операция с каналом вопросов, а не событие шины.** Логин у Pi требует диалога:
показать ссылку, показать код устройства, спросить текст или выбор, сообщить прогресс. По шине это
делать нельзя — событие там уведомление, запрос-ответ запрещён ([event-bus.md](event-bus.md)). Значит
шаги диалога — часть контракта операции входа, и типы шагов объявлены в нашем SDK, а не
реэкспортированы из Pi.

**Доступ — у любого включённого плагина, без системы разрешений.** Границей является факт включения
([plugins.md](plugins.md)); отдельная модель разрешений была бы там же и отвергнута.

**Вход и выход публикуют событие на шину.** Они меняют глобальное состояние, а сделать это может
любой включённый плагин: иначе разлогин, сделанный одним плагином, выглядит для остальных как
внезапная поломка.

## Почему так

Первое решение здесь — **чем едут шаги интерактивного входа.** Владелец продукта выбрал общий поток
событий (2026-07-29). Отвергнутое:

**Ресурс-попытка со своими эндпойнтами и длинным поллингом.** Диалог читался бы `GET`-запросом по
адресу попытки, без всякого потока. Отвергнуто: поллинга в системе нет вовсе — ни короткого, ни
длинного ([web-api.md](web-api.md)), — и ради одного вью пришлось бы завести второй способ узнавать
об изменениях, с собственными таймаутами и собственным поведением при разрыве.

**Второе SSE-соединение на попытку входа.** Шаги шли бы своим потоком, не мешаясь с событиями.
Отвергнуто прямым правилом: второго соединения на вкладку нет ([web-api.md](web-api.md)) — все
события ядра и плагинов идут одним.

**Шаг входа — событие шины.** Механика уже есть, писать нечего. Отвергнуто: событие шины —
уведомление всем подписчикам, а шаг входа адресован одному инициатору и **ждёт ответа**;
запрос-ответ по шине запрещён ([event-bus.md](event-bus.md)). Событием на шину идёт только
свершившийся факт — вход и выход.

**Писатель файла кредов внутри `packages/agent-runtime-pi`.** Форму креда знает этот пакет, ему и
писать. Отвергнуто: все писатели директории данных — модули демона, там же живёт атомарная запись, и
второе место, знающее имена файлов, пришлось бы держать в голове при каждой правке раскладки
([data-directory.md](data-directory.md)). Пакет вместо этого получает порт, а значение креда для
платформы остаётся непрозрачным.

**Полный доступ к кредам, чтение и запись.** Честно отражает реальность — файл плагину и так
доступен. Отвергнуто по сериализации: наличие второго легального писателя означает, что обновление
OAuth-токена перестаёт быть надёжным, а отладка такого отказа стоит дорого.

**Операции плюс чтение значений.** Полезно плагину, который хочет позвать модель сам, минуя нашу
сессию. Отвергнуто: реальная потребность этим не закрывается — прямой вызов модели должен идти нашим
API, иначе на плагине оказывается вся работа с истечением токенов, повторами и учётом стоимости.

**Логин целиком в ядре, плагину только кнопка «войти».** Меньше контракта. Отвергнуто: тогда шаги
диалога рисует ядро, у ядра появляется свой интерфейс входа, и вью провайдеров перестаёт быть
заменяемым.

**Кастомный провайдер — вклад, как компонент или событие.** Так он и числился в
[plugins.md](plugins.md) до реализации: человек переключал бы его отдельно от плагина, и вью плагинов
показывало бы его наравне с остальным. Отвергнуто: вклады применяются одним снимком после `activate`,
а регистрация обязана уметь отказать **на месте вызова** — идентификатор мог быть занят, и плагину
надо знать это прежде, чем он начнёт этим провайдером пользоваться. Цена: по отдельности такой
провайдер не переключается, убирается он только вместе с плагином.

**Кастомный провайдер кодом: плагин приносит функцию запроса и свой способ входа.** Провайдер любой
формы, а не только совместимый с четырьмя протоколами. Отвергнуто по границе: функции не переживают
структурное клонирование, а значит провайдер жил бы в воркере плагина, и каждый запрос к модели ходил
бы туда и обратно — вместе с ключом. Цена принятого варианта записана в пределах выше: OAuth своим
провайдером не объявить, список моделей статический, цены кеша нет.

**Кастомный провайдер заменяет одноимённого встроенного.** Плагин смог бы починить встроенного
провайдера, не дожидаясь нас. Отвергнуто: подмена происходила бы молча, а отличить «мой провайдер» от
«чужой, который я перекрыл» человек не смог бы никак — в снимке остался бы один `id`. Отказ по
занятому идентификатору называет виновника сразу.

**Кред кастомного провайдера уходит вместе с плагином.** Чисто: нет провайдера — нет и креда.
Отвергнуто: перезагрузка плагина — обычное дело (правка исходников), и человек вводил бы ключ заново
после каждой. Цена: в `credentials.json` остаётся запись провайдера, которого больше нет
([backlog.md](backlog.md)).

**Шаги входа отдельным потоком: подписка `providers.onLoginStep(...)`.** Плагин слушал бы шаги
независимо от того, кто начал вход, и рисовал бы диалог даже за человека. Отвергнуто: у вопроса
появилось бы больше одного отвечающего, и платформе пришлось бы решать, чей ответ считать настоящим.
Ключ шага — идентификатор вызова `login`, поэтому чужие шаги плагину не видны вовсе.

**Конец входа — такой же шаг, как остальные.** Один тип на весь диалог, у SDK на один тип меньше.
Отвергнуто: результат операции оказался бы в двух местах сразу — и в шаге, и в возвращаемом значении,
— а плагин, забывший про шаг, узнавал бы об отказе провайдера из тишины.

**Реэкспорт типов протокола из SDK вместо своей копии.** Одно объявление вместо двух, разойтись
нечему. Отвергнуто: SDK ставится внешним плагином из своей папки и внутренних пакетов тянуть не
должен — иначе публикуемая поверхность утаскивает за собой весь `@sovereign/protocol`. Тот же довод
уже решил судьбу `PluginLogLevel` ([plugins.md](plugins.md)).

Цена копии — молчаливое расхождение, поэтому оно **ловится компилятором в мосте демона**
(`apps/daemon/src/plugin-providers.ts`): там на каждый скопированный тип стоит присваивание в обе
стороны, и разъехавшиеся объявления перестают компилироваться. Проверка стоит именно в мосте, потому
что мост — единственное место в системе, где оба объявления видны одновременно.

Цена и следствия:

- плагин не может позвать LLM-провайдера напрямую нашим кредом. Способ обойти есть — прочитать файл
  самому, — но это вне контракта, и наши гарантии на такой плагин не распространяются;
- шаги интерактивного входа становятся публичным типом SDK. Появится провайдер с принципиально другим
  способом входа — контракт придётся расширять, а это версия платформы
  ([public-contract.md](public-contract.md));
- кастомный провайдер, зарегистрированный плагином, исчезает вместе с выключением плагина. Модель,
  выбранная в сессии из такого провайдера, окажется недоступной — что происходит дальше, описано в
  [sessions-and-projects.md](sessions-and-projects.md): сессия доигрывает с тем, что осталось.
