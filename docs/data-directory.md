# Директория данных

Всё состояние платформы лежит в одной директории: перенос установки — это копирование её одной, и
ничего не остаётся в `$HOME` ([ADR-0008](adr/0008-data-directory-config-and-instance-lock.md)).
Путь приходит первым позиционным аргументом запуска, по умолчанию `~/.sovereign_platform`
([ADR-0034](adr/0034-port-and-data-directory-come-from-launch-arguments.md)); в dev-режиме это
`apps/daemon/.sovereign-dev` ([runbook.md](runbook.md)). Отсутствующая директория создаётся при
старте вместе с родительскими.

## Что в ней лежит сейчас

| Файл               | Кто пишет | Назначение                                                           |
| ------------------ | --------- | -------------------------------------------------------------------- |
| `daemon.lock`      | платформа | признак работающего демона, он же защита от второго на тех же данных |
| `config.json`      | человек   | параметры поведения; платформа только читает                         |
| `preferences.json` | платформа | предпочтения пользователя; править руками не запрещено               |

Оба файла настроек необязательны: отсутствующий равен пустому, значения по умолчанию живут в коде.

Решено, но ещё не реализовано: база `state.db` для сессий, журнала и хранилищ плагинов
([ADR-0020](adr/0020-files-for-human-state-sqlite-for-machine-state.md)), папка `work` эфемерного
проекта ([ADR-0045](adr/0045-projects-are-first-class-with-an-ephemeral-default.md)), креды
LLM-провайдеров (ADR-0008).

## `daemon.lock`

Создаётся при старте атомарно, содержит `pid`, момент захвата, имя хоста и порт. Смысл файла — не
дать двум демонам открыть одни и те же данные: делимый ресурс здесь директория, а не порт.

Что происходит при повторном старте на занятой директории:

| Состояние лока                                 | Поведение                                          |
| ---------------------------------------------- | -------------------------------------------------- |
| процесс с этим `pid` жив                       | отказ старта с указанием `pid` и порта работающего |
| `hostname` чужой (директория на сетевом диске) | отказ: проверить процесс на другой машине нечем    |
| процесс мёртв (`kill -9`, падение машины)      | лок считается протухшим и перезахватывается        |
| файл не читается или неполон                   | отказ; лечится удалением файла руками              |

Штатное завершение (`Ctrl+C`, `SIGTERM`) удаляет файл, но только если в нём наш `pid`: чужой лок
платформа не снимает.

Возможен ложный отказ старта — система переиспользовала `pid` мёртвого демона, и живым оказался чужой
процесс. Лечение то же: удалить `daemon.lock` руками, убедившись, что демон действительно не запущен.

## Настройки

Файлов два, и делит их автор записи
([ADR-0033](adr/0033-config-and-preferences-are-separate-hot-reloaded-files.md)). Порта и пути к
директории данных в них нет: это параметры развёртывания, они приходят аргументами запуска.

Поля на сегодня:

| Файл               | Поле       | Значения                               | По умолчанию | Применение |
| ------------------ | ---------- | -------------------------------------- | ------------ | ---------- |
| `config.json`      | `logLevel` | `debug` \| `info` \| `warn` \| `error` | `info`       | живьём     |
| `preferences.json` | —          | полей пока нет                         | —            | —          |

Пример:

```json
{ "logLevel": "debug" }
```

Параметров, требующих перезапуска, сейчас нет. Появится такой — он обязан сказать об этом
диагностикой, а не тихо расходиться с файлом.

### Перечитывание на живом демоне

Оба файла применяются без перезапуска: правка подхватывается за десятки миллисекунд. Наблюдается вся
директория, а не сами файлы, поэтому посторонний файл рядом (`.DS_Store`, временный файл редактора,
лок) события не вызывает — он отфильтровывается по имени. Подробности замеров — в
[runtime-checks.md](runtime-checks.md), проверки 12 и 14.

Перечитывание идемпотентно: если содержимое совпало с текущим, не происходит ничего.

### Что бывает не так

| Что в файле            | Что делает платформа                                                               |
| ---------------------- | ---------------------------------------------------------------------------------- |
| файла нет              | значения по умолчанию                                                              |
| битый JSON             | файл не применяется и не затирается, действует прежний снимок, в лог — диагностика |
| неверное значение поля | то же: применяется файл целиком или не применяется вовсе                           |
| неизвестный ключ       | диагностика, остальное применяется                                                 |

Платформа никогда не перезаписывает `config.json` своим представлением о нём: иначе опечатка в
редакторе уничтожала бы остальные настройки.

## Ручное восстановление

Директория текстовая намеренно: это способ починить платформу, когда интерфейс не открывается.

- **Демон не стартует, жалуясь на лок.** Убедиться, что демон не запущен, и удалить `daemon.lock`.
- **Интерфейс не поднимается из-за настройки.** Править `preferences.json` руками — это
  предусмотренный путь, а не обходной.
- **Не видно, что не так с файлом.** Диагностика идёт в журнал демона: `logLevel` в `config.json`
  ставится в `debug`, и это применяется без перезапуска.

Правка руками при работающем интерфейсе может потеряться: побеждает тот, кто записал последним, а
переключатель в браузере пишет тот же файл.
