# Публичный контракт и версии

Что платформа обещает авторам плагинов и что считается ломающим это обещание.

Плагин объявляет в манифесте диапазон версий платформы, с которыми совместим, и при несовпадении не
загружается ([plugins.md](plugins.md)). Значит версия платформы — публичное число, и правило её
движения должно существовать раньше первого внешнего плагина, а не после.

## Правило

**Semver по объявленному публичному контракту.**

- **Мажор** — удаление или несовместимая смена публичного: пропало имя, изменился смысл, сузился
  принимаемый вход, расширился возможный выход.
- **Минор** — добавление к публичному: новый вид вклада, новое место, новое поле с безопасным
  значением по умолчанию.
- **Патч** — всё, что публичной поверхности не касается.

«Расширился возможный выход» тоже мажор, и это не педантизм: подписчик, разбирающий событие схемой,
ломается от нового варианта так же, как от исчезнувшего поля.

**Устаревание вперёд удаления.** Где возможно, публичное сначала объявляется устаревшим с
диагностикой, и только следующий мажор его убирает — так устроены токены кита
([ui-kit.md](ui-kit.md)).

**Правило действует с первой версии.** Пока все плагины наши, мажор дёшев, но нумерация честная:
вводить правило задним числом, когда диапазон версий уже что-то обещал внешнему автору, нельзя.

Публичная поверхность кита — это ровно то, что он экспортирует из `src/index.ts`: примитивы,
токены (палитра, роли, объявление схемы, `applyRoles` и `applyScale`), список схем поставки
`shippedSchemes` и локализация. Внутренним остаётся всё, что туда не вынесено, — в частности
фокус-трап диалога (`hooks/use-focus-trap.ts`) и счёт перемещения фокуса по кругу
(`components/roving-focus.ts`): это внутренности двух конкретных примитивов, а не то, из чего строят
интерфейс.

Основной entrypoint `@sovereign/browser-sdk` стабилен и сейчас отдаёт на исполнении ровно `Place` и
`PlaceCollection`, а типами — `PlaceContext` и `PlaceProps`. Подпуть
`@sovereign/browser-sdk/host` предназначен только для `apps/web` и публичным контрактом автора
плагина не является. Browser SDK не реэкспортирует UI-кит: первый отвечает за взаимодействие
браузерного UI плагина с платформой, второй — за его вид.

**Мажорная версия React — часть контракта, хотя своей строки в таблице у неё нет.** Браузерная часть
плагина получает React из реестра модулей хоста, а не привозит свой
([ui-extension-model.md](ui-extension-model.md)); значит смена мажора React — ломающее изменение для
каждого плагина с интерфейсом, а не внутреннее обновление зависимости.

**Публичным не является:** внутренности демона, схемы событий чужих плагинов (их совместимость —
ответственность их авторов), номер версии Pi сам по себе. Формат сообщений между ядром и воркером
(`apps/daemon/src/plugins/plugin-wire.ts`) тоже внутренний: обе стороны едут в одной сборке. Публичны при
этом **типы запроса и ответа о провайдерах** — их объявляет SDK, и по ним автор плагина видит, что
именно платформа обещает ответить ([models-and-providers.md](models-and-providers.md)).

**Копии типов протокола в SDK — публичная поверхность, а протокол сам по себе нет.** SDK объявляет
`ProviderSummary`, `ModelSummary` и остальное своей копией, чтобы не тянуть внутренние пакеты в
папку внешнего плагина. Расхождение копии с протоколом обязано быть ломающим изменением обоих, и
проверяется это компилятором в мосте демона, а не глазами.

### Места и вклады в них

Публичны три вещи сразу: **имена мест** базовой поставки, **форма контекста** каждого из них и
**правило разрешения провайдера** ([ui-extension-model.md](ui-extension-model.md)). Новое место —
минор; убрать место или сузить его контекст — мажор.

```ts
type PlaceCardinality = "single" | "collection" | "action";
type PlaceContext = {
  project?: string;
  subject?: Readonly<Record<string, string>>;
};
```

Ключи `subject` — часть контракта места, а не свободная форма: вклад читает их по именам из таблицы
мест. Значения — только строки: контекст пересекает границу «хост → компонент плагина» и обязан
оставаться сравнимым и сериализуемым.

**Пропсы вью базовой поставки публичными не объявлены и не станут.** Плагин, заменивший вью, получает
контекст места и добирает остальное публичными сервисами SDK.

### Агенты, скилы и файловые ресурсы

SDK принимает у `contribute.agent()` необязательные `tools` и `skills` одинаковой формы:

```ts
type AgentToolSelection = { include: string[]; exclude?: string[] };
type AgentSkillSelection = { include: string[]; exclude?: string[] };
```

SDK передаёт объявление без подстановки умолчаний. На границе ядра оба селектора
нормализуются в `{ include: string[]; exclude: string[] }`: отсутствующие селекторы и списки
становятся пустыми, а не неявным `*`. Точная семантика шаблонов описана в
[plugins.md](plugins.md).

Файловый скил попадает в реестр отдельным видом вклада. Он хранит `name`, `location`,
необязательные `license`, `compatibility`, `metadata`, нормализованный `allowedTools?: string[]`
и обязательный `disableModelInvocation`. Plugin-owned-вклад всегда несёт `pluginKey`, `pluginId` и
`source`. Standalone-вклад вместо фиктивного плагина несёт точный `source`, `scope` и, для
проектного корня, `projectId`. Поэтому `AgentSummary.pluginKey` у standalone-агента отсутствует.

Проектные пути `GET /api/projects/:id/agents` и
`GET /api/projects/:id/file-resources` — публичный HTTP-контракт. Второй возвращает один
атомарный снимок:

```ts
type FileResourceKind = "agent" | "skill";
type FileResourceState = "active" | "shadowed" | "switched-off" | "invalid";
type FileResourceDiagnostic = {
  severity: "error" | "warning";
  code: string;
  message: string;
  path: string;
  kind?: FileResourceKind;
  id?: string;
};
type FileResourceSummary = {
  kind: FileResourceKind;
  name?: string;
  id?: string;
  ownership: "standalone" | "plugin";
  scope: "built-in" | "user" | "project";
  source: string;
  path: string;
  state: FileResourceState;
  pluginKey?: string;
  description?: string;
};
type FileResourcesSnapshot = {
  revision: number;
  resources: FileResourceSummary[];
  diagnostics: FileResourceDiagnostic[];
};
```

`revision` связывает снимок с инвалидацией `core.contributions.changed { revision }`;
нагрузка события не дублирует контекстный набор ресурсов.

Конфликт вкладов сохраняет `id`, `source` и массив `plugins`. Для equal-rank standalone-спора к
нему добавляется `standaloneRoots?: string[]` с точными ключами корней, а `plugins` остаётся пустым.
Такой спор виден в project file-resource diagnostics; административный `GET /api/plugins` по-прежнему
возвращает только конфликты плагинов.

**Типы событий Pi публичны, потому что отдаются плагину как есть** ([hooks.md](hooks.md)). Отсюда
правило для обновления рантайма: оно проверяется на изменение публичного так же, как наш собственный
код. Событие исчезло, поле пропало, форма нагрузки поменялась — мажор платформы. Новое событие или
новое поле с безопасным умолчанием — минор. Обновление, не тронувшее события, — патч. Проверка перед
выпуском обязана включать сверку с [agent-runtime-contract.md](agent-runtime-contract.md): это то
место, где расхождение с рантаймом становится видно.

## Ломающие изменения, уже случившиеся

| Что                                   | Когда    | Почему сделано сразу                            |
| ------------------------------------- | -------- | ----------------------------------------------- |
| `/api/session` → `/api/login-session` | срез 9a  | имя `/api/sessions` понадобилось сессиям агента |
| `SessionEntry` вырос с 6 видов до 13  | срез 10b | дерево записей нельзя показать через `other`    |
| `sessions.create` отдаёт исход        | срез 11a | подписчик вправе запретить старт сессии         |

Переименование входа — мажор по правилу выше: имя пропало. Поддержки старого пути нет намеренно.
Держать оба значило бы держать вечно: у состояния входа стало бы два имени, и каждый следующий
читатель кода выяснял бы, какое из них настоящее. Внешних потребителей на момент правки нет, а файл
в директории данных уже назывался `login-sessions.json` — то есть слово «login» в этой роли уже
употреблялось ([data-directory.md](data-directory.md)).

**Расширение `SessionEntry`** — мажор по правилу «расширился возможный выход»: подписчик, разбиравший
запись схемой из шести видов, ломается от седьмого так же, как от исчезнувшего поля. Разобраны все
одиннадцать типов записей рантайма разом, и это решение владельца продукта: сузить поверхность потом
нельзя, а расширить — можно минором, поэтому объём выбран максимальный сразу. `other` остался только
под то, чего рантайм ещё не умеет: обновление Pi, принёсшее новый тип записи, обязано доехать до
клиента хоть чем-то, а не пропасть.

Вместе с ним публичным стал `parentId`: из него строится дерево, и без него весь срез 10b
показывать нечего. Поле существовало и раньше, но публичным его не объявлял ни один документ —
«видно из кода» публичным не делает, так что до этой строки оно публичным не было.

Цена названа прямо: **встроенный плагин остаётся единственным потребителем, и мажор стоит ноль.**
После среза 12 та же правка стоила бы переписки каждого чужого плагина, разбирающего ленту.

**`sessions.create` в SDK возвращает исход, а не сессию** — мажор по тому же правилу «расширился
возможный выход»: подписчик на `before_session_start` вправе запретить старт, и разбирать оба случая
заставляет тип ([hooks.md](hooks.md)). Отказ исключением отвергнут: запрет политикой означает, что
система работает как задумано, и вызывающий, обернувший вызов в `try`, не отличил бы его от упавшего
воркера. Сбои остались исключениями — недоступный проект, занятая сессия, не открывшаяся запись.

`POST /api/sessions` тем же срезом получил `409` со списком отказов ([web-api.md](web-api.md)). Для
HTTP это не мажор: код отказа у создания сессии был и раньше, а поле `refusals` рядом с `error` —
добавка, которую старый клиент не читает.

**Виды вкладов «маршрут» и «публичный маршрут» — минор:** новый вид вклада ничего не отменяет, а
старый клиент, разбирающий снимок `GET /api/plugins`, видит незнакомый `kind` там же, где видел бы
любой другой. Тем же миноры «цветовая схема» и «каталог сообщений» среза 12a. Минором же добавлены
`storage.*` в SDK и три ключа `config.json` ([data-directory.md](data-directory.md)): у всех трёх есть
значения по умолчанию, и файл без них остаётся верным.

**Ограничения на каталог сообщений выбраны в сторону запрета намеренно.** Неймспейс — только `core`
или свой; пустой каталог не принимается. Разрешить чужой неймспейс потом можно, никого не сломав, —
запретить потом уже нельзя, а вклад, у которого запрет снимается минором, стоит дешевле вклада,
запрет у которого приходится вводить мажором.

Вместе с маршрутами публичным стал **адрес** маршрута плагина: он попадает во внешние системы —
вебхук, закладку, редирект, — и сменить его форму значит сломать их все разом.

**Срез 12a сменил эту форму: было `/p/<id плагина>/<путь>`, стало `/api/p/<id плагина>/<путь>`.**
Это **ломающее изменение** публичного контракта, и оно сделано намеренно. Корень `/p/` целиком отдан
браузерным страницам плагина ([ui-extension-model.md](ui-extension-model.md)): оставь мы маршруты на
месте, после среза 13 адрес `/p/hello/board` просили бы одновременно таблица маршрутов и страница, а
различить их по форме нельзя. Цена уплачена в момент, когда она минимальна: внешних потребителей
ноль, маршрут объявляет один тестовый плагин из директории данных. Позже правка стала бы
невозвратной — адрес, уже вписанный в чужой вебхук, не отзывают.

Отдельно: **версия React — часть публичного контракта.** Браузерный код плагина исполняется в realm
хоста и резолвит `react` в экземпляр хоста ([ui-extension-model.md](ui-extension-model.md)), поэтому
мажорное обновление React — ломающее изменение и для плагинов, и для кита. То же относится к `zod`:
он реэкспортируется из SDK ([event-bus.md](event-bus.md)).

## Мажор контракта токенов

У токенов кита свой номер — `tokenContractMajor`, и он не совпадает с версией платформы: цветовая
схема объявляет в поле `tokenContract` тот мажор, на который рассчитана, а кит сверяет его со своим.

**Сейчас `tokenContractMajor` равен 2.** Мажор движется от палитры и только от неё: добавление роли
ничего не ломает, потому что роли выводятся из палитры, а добавление ключа палитры ломает каждую
существующую схему разом — в ней этого цвета просто нет ([ui-kit.md](ui-kit.md)).

**Почему подняли.** Перенос визуала (срез 5, [roadmap.md](roadmap.md)) добавил в палитру два ключа —
`secondary` (второй акцент для редких смысловых меток и надзаголовков) и `shadow` (сдержанная тень
отдельно от затемнения). Оба ушли **одной правкой намеренно:** пока все схемы наши, подъём мажора
стоит ноль, а после среза 12 схему приносит плагин, и такая же добавка станет ломающим изменением
публичного контракта.

**Это окно закрылось.** Плагин объявляет цветовую схему вкладом `contribute.colorScheme`
([plugins.md](plugins.md)), поэтому новый ключ палитры теперь ломает чужие схемы — а значит, поднимает
мажор и требует записи в перечне ломающих изменений выше. Сам вклад добавкой контракта не был: новый
вид вклада ничего прежнего не отменяет, и плагины, написанные до него, продолжают работать.

**Схема с чужим мажором отвергается целиком** — `resolveScheme` возвращает `rejected` с диагностикой
«схема объявляет контракт N, кит говорит на M», и ни один цвет из неё не применяется. Половина верных
цветов хуже внятного отказа: интерфейс, в котором часть ролей осталась от предыдущей схемы, выглядит
работающим и разбирается глазами, а не сообщением. Незнакомая **роль** в точечных переопределениях
ведёт себя иначе — она игнорируется с диагностикой, потому что схему могли написать для более новой
версии кита, и терять из-за одного лишнего имени остальные цвета незачем.

## Почему так

**Мажор на любое изменение публичной поверхности, включая добавление.** Решать ничего не надо,
ошибиться невозможно. Отвергнуто владельцем продукта: на старте мажор выходил бы каждую неделю, и
диапазон версий в манифесте перестал бы что-либо значить — авторы писали бы «любая».

**Не фиксировать правило до первого внешнего плагина.** Скорость сейчас. Отвергнуто владельцем
продукта: манифест уже требует диапазон, то есть обещание уже дано.

**Обещать вечную обратную совместимость SDK.** Авторам плагинов не нужно было бы ничего объявлять.
Отвергнуто: мы потеряли бы право исправлять ошибки в публичном контракте, а политика устаревания
токенов и так исходит из того, что мажоры существуют.

**Считать токены частью версии платформы, без отдельного `tokenContract`.** Один номер вместо двух.
Отвергнуто: цветовую схему приносит вклад — это данные в манифесте, без единой строки кода
([ui-extension-model.md](ui-extension-model.md)). Сверяй схема версию платформы, её отвергал бы любой
мажор — в том числе случившийся в SDK и палитры не касавшийся. Цена принятого варианта: номеров два и
двигать их надо сознательно каждый.

**Копить добавки в палитру и поднимать мажор токенов по одной.** Каждый ключ виден отдельно, и
понятно, что именно сломалось. Отвергнуто: у подъёма мажора цена не в номере, а в том, что все
существующие схемы надо переписать; два ключа одной правкой — одна переписка вместо двух. Пока схемы
только наши, момент для этого дешёвый и им надо пользоваться, а не растягивать.

Цена:

- пометка «публичное» становится обязательной частью документа об интерфейсе. Документ без неё
  оставляет вопрос открытым, а значит проверка перед выпуском невозможна — за этим придётся следить
  при обзоре, механизмом это не проверяется;
- выпуск перестаёт быть механическим действием: перед ним кто-то обязан сказать, что изменилось в
  публичном;
- правило придётся применить к самим себе раньше, чем появятся внешние авторы: встроенные плагины
  живут поверх того же SDK и первыми обнаружат ломающее изменение.
