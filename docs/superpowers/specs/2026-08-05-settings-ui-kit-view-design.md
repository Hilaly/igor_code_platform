# Базовое вью Settings в UI kit

## Цель

Все разделы настроек используют одно базовое вью из `@sovereign/ui-kit` и буквально повторяют
плотную master–detail-геометрию утверждённого мокапа. Projects, включая список и деталь проекта,
является таким же вложенным разделом, как Appearance, Providers, Plugins, Daemon и Diagnostics.

## Визуальный контракт

`SettingsView` UI kit владеет всей общей геометрией:

- компактный верхний bar с названием текущего контекста;
- узкая вертикальная навигация без отдельной карточки;
- выбранная строка с акцентной заливкой, а не крупной кнопкой с обводкой;
- тонкий вертикальный разделитель между навигацией и содержимым;
- компактный serif-заголовок раздела и короткое описание;
- плоская рабочая область без вложенных панелей;
- строки настроек с названием и пояснением слева и контролом справа;
- тонкие горизонтальные разделители между строками.

Размеры, типографика, поверхности и состояния берутся только из токенов UI kit. Мокап является
источником истины для плотности и пропорций. Крупный breadcrumb `Sovereign · Settings`, огромные
заголовки и обведённые активные пункты в этот контракт не входят.

## Публичные компоненты

UI kit экспортирует:

- `SettingsView` — общий каркас с bar, локальной навигацией и областью содержимого;
- `SettingsNavigationItem` — компактный пункт с `selected` и доступным состоянием выбора;
- `SettingsPage` — заголовок, описание и содержимое одного раздела;
- `SettingsRow` — строка `label + description / control` для плотных форм.

Компоненты принимают готовое предметное содержимое и callbacks, но не знают маршруты, проекты,
провайдеров или плагины. `apps/web` владеет данными и навигацией, а не визуальной геометрией.

## Вложенные экраны

Все шесть разделов используют `SettingsPage`. Appearance и Daemon собирают формы из `SettingsRow`.
Списки и детали Projects, Providers и Plugins размещаются в той же области и используют её плотность,
заголовок и разделители; они не рисуют второй заголовок страницы и самостоятельный внешний каркас.
Diagnostics также остаётся плоским содержимым страницы.

На деталях верхний bar и локальная навигация не исчезают. Заголовок страницы меняется на название
объекта, а возврат к списку является компактным действием внутри содержимого.

## Адаптивность и доступность

Адаптивность определяется шириной контейнера. При нехватке места навигация становится одной
горизонтальной прокручиваемой строкой над содержимым. На ещё более узкой ширине `SettingsRow`
складывается в одну колонку. Выбранный пункт имеет `aria-current="page"`, все контролы сохраняют
связи label/description, а на странице остаётся один `h1`.

## Проверка

- render-тесты UI kit доказывают структуру bar, навигации, страницы и строки;
- CSS-контракт доказывает компактные колонки, акцентную заливку, serif-заголовок и адаптивные режимы;
- component-тесты web доказывают использование общей структуры каждым разделом и отсутствие
  повторных заголовков;
- live QA сравнивает Appearance, Projects list/detail, Providers list/detail, Plugins list/detail,
  Daemon и Diagnostics с мокапом на широкой и узкой области;
- test, typecheck, ESLint, Prettier и production build проходят для UI kit, web и workspace.

## Почему так

**Геометрия принадлежит UI kit.** Только общий публичный компонент не позволяет разделам снова
разойтись по отступам, заголовкам и выбранным состояниям. CSS в `apps/web` остаётся только для
предметного содержимого.

**Один составной Settings API вместо универсальных Panel/List.** Прежняя сборка из крупных общих
компонентов формально давала master–detail, но наследовала неподходящие размеры и состояния. Явные
примитивы Settings фиксируют утверждённую плотность без глобального изменения всех списков продукта.

**Мокап, а не прежняя реализация, является эталоном.** Сохранение текущего breadcrumb, крупного h1
или обведённого `ListRow` отвергнуто: именно эти элементы создали визуальное расхождение.

**Projects не является исключением.** Отдельная композиция списка или детали снова создала бы два
визуальных контракта настроек. Предметная логика Projects сохраняется, внешний каркас и заголовки
принадлежат общему вью.
