# Глобальная шапка shell для всех рабочих вью

## Статус

Согласовано владельцем продукта 6 августа 2026 года. Следующий шаг — отдельный план реализации
после ревью этого документа.

## Цель

Сделать верхнюю часть центральной колонки постоянной и узнаваемой частью оболочки Sovereign. Она
соответствует выбранному варианту A: одна компактная строка, которая остаётся наверху во время
прокрутки любой рабочей view. Содержимое строки меняется при переходе между окнами, но её
геометрия, поверхности и ритм принадлежат shell и UI kit.

## Не входит в задачу

- редизайн левой и правой панелей;
- новые глобальные команды (`⌘K`, поиск, меню приложения), пока их нет в действующем контракте;
- изменение маршрутизации или поведения действий отдельных view;
- шапка экрана входа: до аутентификации shell не монтируется;
- предметные данные, которых текущие контроллеры ещё не умеют получить.

## Визуальный контракт

Шапка — постоянная строка примерно 52–54 px в верхней части центральной колонки. Она использует
поверхность центральной страницы, не превращается в отдельную карточку и имеет тонкий нижний
разделитель роли `borderSubtle`.

Слева располагаются обязательный для рабочего окна `title` и необязательный `context` — компактная
мета-информация (например, проект, путь, модель или состояние). Справа располагается необязательный
`actions`. Действия создаёт конкретная view и передаёт уже готовые UI-kit-контролы. Shell не
интерпретирует их и не добавляет фиктивные кнопки.

Если `context` или `actions` не переданы, слот и его декоративные элементы не рендерятся и не
занимают отдельное место. Длинные значения не растягивают центральную область: примитив применяет
предсказуемое усечение и сохраняет доступное полное имя. На узкой ширине действия могут переноситься
на вторую строку внутри той же шапки; заголовок и контекст сохраняют приоритет.

## Архитектура и границы

UI kit расширяет существующий нейтральный `ViewHeader`, а не создаёт второй почти одинаковый
компонент. Публичный примитив принимает:

```ts
type ViewHeaderProps = {
  title: ReactNode;
  context?: ReactNode;
  level?: 1 | 2 | 3;
  actions?: ReactNode;
};
```

`title` остаётся настоящим заголовком; `context` — отдельный нейтральный слот рядом с ним. Кит
владеет семантикой `header`, флекс-геометрией, типографическими ролями, разделителем, переносом и
доступным усечением. В кит не попадают строки, зависящие от маршрута, и предметные кнопки.

`Shell` получает описание:

```ts
type ShellHeader = {
  title: ReactNode;
  context?: ReactNode;
  actions?: ReactNode;
};
```

Shell всегда монтирует центральный header и передаёт слоты в `ViewHeader`. Shell отвечает за порядок
областей, высоту и то, что шапка не прокручивается. Вью отвечает за смысл заголовка, fallback-и,
мета-информацию и действия.

Центральная колонка раскладывается в две строки: постоянный `header` и остаток для тела view. У
обычной page-view остаток остаётся scroll-контейнером. У `contentMode="contained"` (агентская
сессия) header находится вне внутреннего контейнера с лентой: прокручивается только история, а
композер и нижняя рабочая зона сохраняют существующую самодостаточную раскладку. `position: sticky`
и абсолютное закрепление для этой задачи не используются.

## Заполнение текущих окон

| Окно                 | `title`                                      | `context`                                        | `actions`               |
| -------------------- | -------------------------------------------- | ------------------------------------------------ | ----------------------- |
| Home                 | `Sovereign` или локализованный title раздела | отсутствует                                      | отсутствуют             |
| Session              | название сессии, fallback «Новая сессия»     | проект и компактный статус/модель, если известны | fork, compact, menu     |
| Archive              | «Архив сессий»                               | отсутствует                                      | отсутствуют             |
| New session          | «Новая сессия»                               | выбранный проект, если выбран                    | отсутствуют             |
| Settings             | «Настройки»                                  | название активного раздела                       | только действия раздела |
| Project detail       | название проекта                             | путь проекта                                     | существующие edit/menu  |
| Providers            | «Провайдеры»                                 | отсутствует                                      | add provider            |
| Provider detail/form | имя провайдера или режим формы               | тип/состояние, если доступны                     | edit/save/delete        |
| Plugins              | «Плагины»                                    | отсутствует                                      | отсутствуют             |
| Plugin detail        | имя плагина                                  | версия/состояние, если доступны                  | enable/menu             |
| Unknown/plugin page  | fallback title                               | адрес/идентификатор при необходимости            | отсутствуют             |

Точный текст берётся из существующего translator-контракта. Если данные ещё не получены, view
передаёт только стабильный title и не рисует догадки в context.

## Поток данных

Маршрут и контроллеры приложения по-прежнему выбирают и собирают view. Перед вызовом `Shell` слой
`App` вычисляет описание шапки для текущего `Page` из уже доступных данных. Новых HTTP-маршрутов,
событий или глобального состояния шапки не появляется.

Смена маршрута меняет header атомарно с телом view. Смена заголовка сессии, модели или статуса не
сбрасывает draft композера и не меняет layout панелей.

## Доступность

- На странице остаётся один главный заголовок; его уровень выбирает композиция, а не CSS.
- Header имеет семантический `header`.
- Каждое icon-only действие обязано иметь `aria-label` и `title` по контракту `Button`.
- Усечённые значения получают доступное полное имя через `title`/описание.
- Фокус и порядок табуляции принадлежат переданным действиям; shell не добавляет невидимых
  фокусируемых элементов.

## Проверка

UI kit проверяет `header`, уровень заголовка, отсутствие пустых слотов, context, actions, перенос и
усечение; существующие тесты `ViewHeader` обновляются вместо параллельного набора.

Web/shell проверяет постоянный header перед телом, две строки композиции, отсутствие `sticky` и
абсолютного закрепления, описания для всех текущих `Page.kind`, атомарную смену при навигации,
независимый scroll сессии и обычных страниц. После focused-тестов выполняются typecheck, lint,
форматирование, Ladle build и web build. Браузерная проверка охватывает широкое и узкое окно,
длинное имя, пустые slots, длинную историю сессии и скрытие/возврат панелей.

## Почему так

**Один примитив UI kit вместо отдельного `ShellHeader`.** Шапка страницы и рабочего окна имеют одну
семантику: заголовок плюс необязательные действия. Разведение компонентов привело бы к расхождению
типографики, переносов и доступности.

**Shell владеет постоянством, view — содержимым.** Только shell знает границу центральной колонки и
scroll-контейнер, а только view знает смысл заголовка и доступные действия.

**Grid из header и scroll-body вместо `position: sticky`.** Шапка постоянна относительно shell, а не
конкретного DOM-дерева. Sticky и абсолютное позиционирование ломались бы при нескольких вложенных
scroll-контейнерах и будущих параллельных чатах.

**Пустые слоты действительно отсутствуют.** Декоративные пустые бейджи и заготовленные места
создают визуальный шум и лишают view возможности быть компактной.

**Глобальные команды пока не добавляются.** У продукта ещё нет утверждённого контракта поиска или
командного меню, поэтому их нельзя придумывать внутри shell.
