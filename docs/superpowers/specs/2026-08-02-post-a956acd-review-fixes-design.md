# Исправления по ревью после `a956acd`

## Цель

Вернуть поведение, уже обещанное документацией, и закрыть шесть регрессий, появившихся в коммитах
после `a956acd`, без расширения области задачи и без новых зависимостей.

## Поведение

- Восстановленная правая панель оболочки видна даже при пустом списке вкладок и показывает
  существующую заглушку. Когда вкладки появятся, их полоса остаётся доступной.
- `providerId` в адресе страницы провайдера кодируется как один URL-сегмент и безопасно
  декодируется при разборе. Идентификаторы со слешем, пробелом и Unicode проходят полный круг
  `page -> path -> page`; испорченная percent-кодировка становится неизвестным маршрутом.
- Кнопка подтверждения внутри `Form` является нативной кнопкой `submit`. `Button` сохраняет
  безопасный `type="button"` по умолчанию и принимает явный `type="submit"`, поэтому Enter в поле
  снова подтверждает вход или создание проекта без ручных обработчиков клавиатуры.
- При переходе FilePicker в другой каталог приложение сразу очищает прежние элементы, ошибку и
  выбранное значение. В пикере папки проекта показываются только каталоги: файл нельзя подтвердить
  как папку проекта.
- `GET /api/filesystem` принимает только абсолютный `path`; относительный путь получает `400` в
  общей форме `{error}` до обращения к файловой системе.

## Границы изменений

Общий `FilePicker` остаётся нейтральным к типу выбираемого элемента: фильтрация файлов относится к
конкретному сценарию выбора папки проекта. Формат ответа filesystem API и остальные маршруты не
меняются. Единственное расширение публичного API UI-кита — необязательный `Button.type` со значением
`"button"` по умолчанию и явным `"submit"` у подтверждающих кнопок форм. Новых зависимостей не
добавляется.

## Проверка

Для каждой регрессии сначала добавляется тест, который воспроизводит дефект, затем минимальная
правка. После тематических тестов выполняются полные `make check` и `make build` на Node из
`.nvmrc`. Изменения разбиваются на атомарные коммиты, каждый с обязательным трейлером соавтора.
