# Индекс проектов и страница проекта

## Контекст

Вью проектов уже умело создавать, архивировать и удалять записи, но список был тяжёлым для
просмотра: не было поиска, карточка не открывалась, а подробности проекта смешивались с формой
создания.

## Решение

Выбран вариант C — индекс проектов:

- сверху остаются заголовок, поиск по имени и пути и заметная кнопка «Новый проект»;
- каждый активный проект отображается отдельной кликабельной строкой-карточкой;
- меню `…` находится в отдельной зоне действий строки и не запускает переход по карточке;
- архивные проекты сохраняются в раскрываемой секции;
- поиск выполняется на клиенте по `name` и `folder`, поэтому результат меняется без нового запроса;
- переход ведёт на адрес `/projects/:id`, а кнопка «Назад к проектам» возвращает в индекс.

Страница проекта показывает имя, папку, доступность каталога, эфемерность и число сессий. Ниже
переиспользуется существующая вью сессий; хук получает `projectId` и запрашивает уже поддержанный
демоном фильтр `GET /api/sessions?projectId=...`.

## Почему так

Новый API для поиска не нужен: проектов обычно немного, а локальная фильтрация даёт мгновенный
отклик и не усложняет поток состояния. Идентификатор проекта, а не папка, используется в URL — папка
может содержать юникод и меняться по написанию, тогда как `id` стабилен. Внутри карточки используется
примитив `ListRow`, чтобы сохранить клавиатурную навигацию UI-кита; контекстное меню остаётся
действием, не вложенным в кнопку перехода.
