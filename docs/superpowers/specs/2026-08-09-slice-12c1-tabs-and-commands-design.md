# Срез 12c-1: вкладки правой панели и команды

## Цель

Плагин приносит вкладку в правую панель оболочки, которая стоит пустой заглушкой с среза 4a, и команду,
вызываемую кнопкой, палитрой и чужим плагином. Срез закрыт, когда на собранном демоне вкладка плагина
появилась подписью до загрузки бандла, открылась, пережила перезагрузку страницы и вернулась после
выключения и включения вклада; а команда плагина исполнилась и кнопкой в шапке, и из палитры, где рядом
с ней стоят команды ядра.

Утверждённое роадмапом содержание среза 12c не сужается: страницы плагина на `/p/<pluginId>/<pageId>/*`
идут второй частью, 12c-2, отдельной веткой.

## Четвёртая кардинальность

`placeCardinalities` растёт до четырёх значений:

```ts
export const placeCardinalities = ["single", "collection", "action", "tabs"] as const;
```

Перечень лежит в двух пакетах — `packages/protocol/src/contribution.ts` и его копия
`packages/sdk/src/host.ts`, — и оба публичны. Копия существует потому, что SDK плагина не зависит от
протокола; расхождение ловится тестом.

Коллекции для вкладок не хватает по механической причине, а не по оформительской: **у коллекции
рисуются все экземпляры сразу, у вкладок — ровно один, а остальные существуют подписями.** Оставь место
коллекцией — и `PlaceCollection` любого плагина честно, по контракту, вывалит все вкладки стопкой к себе
на страницу. Места однородны, значит разница «полоса против стопки» обязана быть в объявлении места, а
не в том, кто его рисует.

Заголовок при этом становится несущим. У вклада в коллекцию `title` — украшение: компонент рисует себя
сам. У вклада во вкладку `title` — единственное, чем вкладка представлена до загрузки кода. Сказать
«заголовок здесь обязателен» можно только кардинальностью.

Цена названа вслух: значение из публичного перечня потом не убрать, и каждый разбор кардинальности
получает четвёртую ветку. Существующая проверка демона `replaceable && cardinality !== "single"`
покрывает `tabs` без правки — заменяемых вкладок не бывает по построению.

## Место `core.panel.tabs`

```ts
// packages/protocol/src/places.ts, в corePlaces
/** Вкладки правой панели. Полосой и выбором открытой владеет оболочка. */
{ id: "core.panel.tabs", cardinality: "tabs", replaceable: false },
```

Имя по образцу `core.sidebar.sections`: `core.<область>.<что>`. «sidebar» занята левой панелью, поэтому
«panel» без уточнения читается как правая.

Контекст — тот же `pageContext`, что у секций левой панели и полосы действий шапки:
`{ subject: { page: page.kind } }`, **без `project`**. Правая панель общая на всё окно, и плагин из папки
открытого проекта не вправе принести в неё вкладку — тот же довод, по которому проектный вклад не
занимает оконное вью.

Вклад-вкладка — обычный `kind: "component"` с `placeId: "core.panel.tabs"`; плагин не учит ничего нового:

```ts
await contribute.component({
  id: "board",
  title: "Board",
  placeId: "core.panel.tabs",
  export: "BoardTab",
  order: 1,
});
```

Подпись вкладки — `title ?? declaredId`. Требовать `title` при регистрации нельзя: реестр не знает
кардинальности места, потому что место вправе ещё не существовать — «вклад в неизвестное место ждёт» это
записанный инвариант. Запасной вариант детерминирован и диагностики не требует.

Порядок — существующий `orderPlaceContributions`: группа, затем `order`, затем идентификатор вклада.
Появление нового плагина не переставляет соседей.

Место берёт **только** `kind: "component"`: у вкладки обязано быть содержимое, и команда его не даёт.

### Что оболочка получает

Проп `tabs` у `Shell` — опубликованный контракт размещения, и он не меняется. Список собирает новый хук
host-entrypoint браузерного SDK:

```ts
// @sovereign/browser-sdk/host
export type HostPlaceTab = { id: string; label: string; content: ReactNode };
export function useHostPlaceTabs(props: PlaceProps): HostPlaceTab[];
```

Тип структурно совпадает с `ShellTabDescription`, поэтому в `apps/web/src/App.tsx` меняется одна строка.
`id` вкладки — идентификатор вклада с неймспейсом (`placed.board`): он стабилен между ревизиями и годится
ключом в `localStorage`.

`content` — созданный, но не смонтированный элемент `PlaceInstance`. `Shell` рисует только открытую
вкладку, значит **бандл закрытой вкладки не грузится**: кеш модулей трогает тот, кто отрисовался, а не
тот, кого положили в массив.

### Забытый идентификатор открытой вкладки не чистится

`openTab`, указывающий на вклад, которого сейчас нет, **остаётся в раскладке как есть**. `Shell` уже
разбирается: `tabs.find(...)` даёт `undefined`, панель показывает заглушку.

Чистить нельзя, и это решение, а не бездействие: плагин исчезает из снимка на каждой пересборке — между
правкой исходников и готовым бандлом он проходит через `building`, и браузерной части у него нет. Вычистив
идентификатор, мы закрывали бы вкладку человека при каждой правке плагина. Модель говорит ровно это:
«Место исчезло — вклад снова ждёт, не теряя сохранённого размещения».

Значит здесь нужен тест, а не код.

### Сторона плагина

Ради однородности публикуется и плагинская полоса вкладок:

```ts
// @sovereign/browser-sdk
export function PlaceTabs(props: PlaceProps): ReactNode;
```

Требует объявления с `cardinality: "tabs"`, иначе рисует пусто — так же, как `Place` и `PlaceCollection`
отвергают место чужой кардинальности. Открытая вкладка — обычный `useState` внутри: это «небольшое
состояние» по таблице уровней, живущее до размонтирования. Цена: полоса плагина забывает выбор при
размонтировании; управляемые `value`/`onChange` появятся вместе с плагином, которому это помешает.

### ARIA полосы вкладок

`role="tablist"` вместе с `Button pressed` (`aria-pressed`) — рассогласование, и с появлением настоящих
вкладок его надо снять. Вкладку в оболочке можно **закрыть повторным щелчком**, а `role="tab"` этого не
допускает: у него выбран ровно один. Полоса объявляется группой кнопок-переключателей, чем она и
является.

Отвергнуто: сделать настоящие `role="tab"`/`aria-selected` через новые пропсы кита. Дороже и отбирает у
полосы закрытие щелчком, то есть меняет поведение ради ярлыка.

## Вид вклада «команда»

```ts
// packages/sdk/src/host.ts
export type CommandContribution = {
  id: string;
  /** Обязателен, в отличие от общего: заголовок — то, чем команду называют кнопке и палитре. */
  title: string;
  description?: string;
  /** Имя экспорта в браузерном бандле плагина: дескриптор команды. */
  export: string;
  /** Место кардинальности «действие», куда хост поставит кнопку. Не сказано — кнопки нет. */
  placeId?: string;
  group?: string;
  order?: number;
};
```

```ts
// packages/protocol/src/contribution.ts
export type CommandContributionRegistration = RegistrationCommon & {
  kind: "command";
  title: string;
  export: string;
  placeId?: string;
  group?: string;
  order?: number;
};
```

**Поля `handler: "browser" | "worker"` нет намеренно.** Наличие `export` уже означает «обработчик в
бандле» — ровно так же, как `builtIn` у места означает «встроенный провайдер там же». Когда появится
воркерный обработчик, `export` станет необязательным, и это additive-изменение; отдельное поле было бы
вторым способом сказать то же.

Реестр демона проверяет: у плагина объявлена браузерная точка входа (иначе ссылаться экспортом не на
что), `title` непуст, `export` непуст, `placeId` — если задан — совпадает с `placeIdPattern`, `group`
строка, `order` конечное число. **Существование места не проверяется**: вклад ждёт, как ждёт компонент.

Общий тип размещаемых вкладов:

```ts
export type PlacedContributionRegistration =
  ComponentContributionRegistration | CommandContributionRegistration;
```

Рядом с `componentsForPlace` появляется `contributionsForPlace`, отбирающая оба вида по тем же правилам
контекста и ранга; `orderPlaceContributions` переходит на неё и расширяет возвращаемый тип.
`componentsForPlace` **не трогается**: её потребитель — `resolvePlaceProvider`, а команда одиночное место
занять не может, и подмешивать её туда значило бы разрешить команде спорить за провайдера.

### Обработчик и вызов

```ts
// @sovereign/browser-sdk
export type Command = {
  run(context: PlaceContext): void | Promise<void>;
  /** Условие доступности: обычный предикат в том же realm. Нет — команда доступна всегда. */
  available?(context: PlaceContext): boolean;
};

export type CommandOutcome =
  | { kind: "done" }
  | { kind: "unavailable" }
  /** Такой команды нет в действующем наборе этого контекста. */
  | { kind: "unknown" }
  /** Бандл не загрузился, экспорта нет, обработчик бросил. */
  | { kind: "failed"; reason: string };

export function useCommands(): {
  invoke(commandId: string, context?: PlaceContext): Promise<CommandOutcome>;
};
```

`invoke` **никогда не бросает**: команда — действие интерфейса, и исключение из неё уронило бы дерево
React. Отказ приезжает значением и дополнительно уходит в диагностику тем же дедуплицированным голосом,
которым жалуются места.

Хук, а не свободная функция: адрес команды разрешается по тому же снимку и по тем же правилам контекста и
ранга, что и место, а снимок с кешем модулей лежат в `BrowserRuntimeContext`. Отсюда само собой выходит
«команду вызывает другой плагин» — идентификатор чужой, как бывает чужим `placeId`.

Вызов, осиротевший размонтированием провайдера посреди загрузки бандла, **завершается исходом `failed`, а
не висит вечно**: это отдельная проверка, а не следствие.

### Кнопка в месте кардинальности «действие»

`CollectionPlace` начинает разбирать два вида вкладов. Для команды рисуется китовая `Button` с `title`
**из снимка, до загрузки бандла**. В этом и выигрыш метаданных: полоса не прыгает, порядок известен
сразу, а плагин со сломанной сборкой оставляет кнопку, которая честно отвечает отказом, вместо пустоты.

`packages/browser-sdk` получает зависимость на `@sovereign/ui-kit`. Цикла нет — кит зависит только от
протокола; в бандл плагина кит не попадает, он уже во внешних и резолвится из реестра модулей хоста.
Цена: стабильность кита въезжает в контракт браузерного SDK, и это законно ровно потому, что кит объявлен
стабильным.

### Почему `available` не становится отвергнутым `when`

Модель отвергла декларативный мини-язык условий видимости. Три замка держат это решение:

1. **Условие — функция, а не данные.** Оно живёт в браузерном бандле рядом с `run` и границу воркера не
   пересекает. Мини-язык нужен тогда, когда условие обязано доехать данными; здесь оно не обязано именно
   потому, что и обработчик в браузере.
2. **В реестре условия нет вовсе.** У `CommandContributionRegistration` нет ни `when`, ни `enablement`,
   ни `contextKeys`. Записать условие в объявление нечем, значит и разбирать нечего.
3. **Хост не обещает решать без кода.** Пока бандл не загружен, кнопка нажимается; загруженный бандл
   делает её честной. Обещание «решить, показывать ли, **не загружая** код» и потребовало бы
   декларативного языка — мы его не даём.

Отсюда терминологический замок: у команды есть `available`, но не `visible`. Скрыть вклад нельзя —
исчезающая кнопка требует решения до загрузки кода; выключенная не требует, потому что деградирует мягко.

Цена названа: до загрузки бандла команда выглядит доступной, и щелчок по ней возвращает `unavailable`.

## Команды ядра и палитра

**Команды ядра — данные хоста, а не вклады.** Они живут списком в `apps/web`, в реестр демона не
попадают, в снимке `/api/plugins` их нет. Прецедент — второй источник строк у диспетчера маршрутов:
таблица собирается из постоянной части и из динамической, и это не сделало обе одинаковыми.

```ts
// apps/web/src/commands/core-commands.ts
export type CoreCommandHost = {
  navigate: (page: Page) => void;
  layout: ShellLayout;
  onLayoutChange: (layout: ShellLayout) => void;
};

export type CoreCommand = {
  id: `core.${string}`;
  titleKey: string;
  run(host: CoreCommandHost): void;
  available?(host: CoreCommandHost): boolean;
};
```

Начальный набор — только то, что оболочка уже умеет: новая сессия, архив сессий, шесть разделов настроек,
показать и скрыть каждую панель. Ни одна команда не заводит нового поведения — все зовут `navigate` или
`onLayoutChange`. Выключить встроенную команду нельзя, как нельзя выключить встроенное вью.

**Палитра — часть оболочки, а не заменяемое место.** Модель говорит «оболочка принадлежит ядру и не
заменяется»; палитра — такая же его собственность, как полоса вкладок и границы панелей. Композиция
`apps/web` из готовых примитивов кита (`Dialog`, `Input`, `ListRow`) — тот же довод, по которому блок кода
устройства не стал примитивом: плагину, который захочет свою палитру, нужны части, а не наша компоновка.
Сделать палитру заменяемым местом можно потом минором; снять имя из публичного контракта — нельзя.

Палитра показывает команды ядра и команды плагинов **одним списком**, без разделения на источники: для
человека это одинаковые действия, а различие источников видно во вью плагинов. Фильтр — подстрочный по
заголовку, выбор — `Enter`, закрытие — `Escape` (даёт `Dialog`).

Точек входа две, и обе обязательны: аккорд **Cmd/Ctrl+K** с `preventDefault` и **видимая кнопка в
оболочке**. Кнопка не украшение: узкий экран — требование вижна, а на телефоне аккорда нет вовсе.

Аккорд один и принадлежит ядру. Назначения аккордов командам плагинов в срезе нет.

## Состояние экземпляра в срез не входит

Бэклог предполагал спроектировать сохранение небольшого состояния UI-экземпляра «вместе с первым
потребителем, например вкладками правой панели». Чтением кода догадка не подтвердилась:

- **открытая вкладка — не состояние экземпляра, а раскладка хоста**, и таблица уровней в
  [ui-extension-model.md](../../ui-extension-model.md) прямо кладёт её в строку «локально в браузере».
  Это `ShellLayout.openTab`: он уже есть, уже в `localStorage`, уже переживает перезагрузку;
- у экземпляра вкладки не теряется ничего заметного: прокрутка и раскрытые секции живут внутри кода
  плагина, и носитель такой же длительности жизни у плагина уже есть — переменная уровня модуля в его
  бандле живёт ровно столько, сколько ревизия;
- проектировать ключ экземпляра, правила версионирования и момент забывания без потребителя — ровно то,
  что модель отвергла у `when`.

Пункт бэклога остаётся с **исправленной** формулировкой: первым потребителем будет не полоса вкладок, а
плагин, которому надо пережить перезагрузку страницы. Цена до тех пор: такой плагин пишет в своё
хранилище в директории данных, а это не тот уровень — состояние уедет между машинами.

## Не входит в работу

- страницы плагина на `/p/<pluginId>/<pageId>/*`, переделка роутера под query-параметры и `replace`,
  фасад навигации, вид вклада «страница» — срез 12c-2;
- горячие клавиши, назначаемые командам плагинов: второй реестр споров рядом с существующим, конфликты
  с браузером и ОС, поверхность переназначения в предпочтениях;
- воркерный обработчик команды и вызов команды из воркера;
- несколько размещений одной команды: сегодня одно `placeId`, кому мало — экспортирует компонент,
  который зовёт `invoke`;
- перевод заголовка команды и подписи вкладки каталогом локали плагина;
- палитра как заменяемое место `core.command.palette`;
- сохранение небольшого состояния UI-экземпляра.

## Проверка

Живой сценарий на собранном демоне из чистой временной директории данных, тем же способом, что «Места и
вклады плагина живьём»:

- вкладка плагина появилась подписью из снимка **до загрузки бандла**;
- открытие вкладки грузит бандл, закрытая вкладка не грузит;
- выбор вкладки пережил перезагрузку страницы;
- выключение вклада показало заглушку, **не стерев** `openTab`; включение вернуло ту же вкладку открытой;
- упавшая вкладка не уронила оболочку и пожаловалась в диагностику;
- команда плагина стоит кнопкой в полосе действий шапки и исполняется щелчком;
- `available → false` выключает кнопку после загрузки бандла;
- палитра открывается кнопкой и аккордом, на чистой установке без плагинов показывает команды ядра, после
  включения фикстуры — обе группы одним списком; фильтр, `Enter`, `Escape`;
- правка исходников плагина проводит его через `building` и не гасит страницу.

Перед каждым коммитом — `make check` (typecheck, lint, формат, тесты). Перед переписыванием истории и
после него — `make check`, `make build`, `git diff --check` и повторный живой прогон.

## Почему так

### Срез 12c разрезан, и вкладки идут раньше страниц

**Одной веткой целиком.** Один связный контракт, одна приёмка. Отвергнуто владельцем продукта: объём
сопоставим со срезом 12b, который резался надвое, а мажор публичного контракта — четвёртая кардинальность
плюс новый вид вклада плюс рост браузерного SDK — принимался бы разом, без возможности остановиться.

**Сначала страницы.** Раньше появляется самая заметная возможность — «плагин занимает целую страницу».
Отвергнуто: страницы стоят на предпосылке, которой сегодня нет. `createNavigation` работает только с
`pathname`: `navigate` стирает query-строку при любом переходе, а переход, меняющий только параметры,
молча не происходит. Требование модели «плагин получает от хоста базовый путь, относительный путь,
**параметры** и фасад навигации» исполнить нечем, пока это не починено. Вкладки и команды такой
предпосылки не имеют — они ложатся на опубликованный проп `tabs` и существующее место «действие».

### Команды ядра — данные хоста, а не вклады встроенного плагина

**Завести встроенный плагин с командами ядра.** Один источник команд, ноль новых понятий, команды видны
во вью плагинов наравне с чужими. Отвергнуто: у вклада есть переключатель, и «выключить команду
`core.session.new`» получилось бы само собой — состояние, в которое интерфейс приводить нечем. Встроенные
вью по той же причине не выключаются, а заменяются.

Цена принятого варианта названа прямо: источников команд два, и палитра обязана их сложить. Она их и
складывает — в один список, потому что для человека это одинаковые действия.

### Палитра, а не только кнопка

Роадмап обещал команды; палитра — решение владельца продукта поверх обещанного. Без неё команда достижима
только там, где плагин попросил кнопку, то есть вся ценность «одна команда — много точек вызова»
осталась бы словами: вторая точка вызова появилась бы только с горячими клавишами, а они уехали.

Отвергнуто: **обойтись местом «действие»**. Дешевле на один экран, но тогда срез не проверяет главного
своего утверждения, а на чистой установке без плагинов не проверяет вообще ничего.

### Кнопка палитры, а не только аккорд

**Только Cmd/Ctrl+K.** Так делают редакторы, и лишнего элемента в шапке не появляется. Отвергнуто: узкий
экран — требование вижна, а не отдельная работа по адаптации; на телефоне аккорда нет вовсе, и палитра
оказалась бы недостижимой. Плюс невидимая точка входа не проверяется глазами при живой проверке.
