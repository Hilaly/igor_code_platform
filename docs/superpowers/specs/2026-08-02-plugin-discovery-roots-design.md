# Каталог проектных плагинов

## Цель

Изменить только расположение плагинов внутри проекта:

```text
<project>/plugins/ → <project>/.sovereign/plugins/
```

Пользовательский каталог `<data-directory>/plugins/` и встроенные плагины остаются без изменений.
Каталоги `.agents/plugins/` не поддерживаются.

## Поведение

Источники плагинов после изменения:

| Source                 | Путь                            | Ранг | По умолчанию |
| ---------------------- | ------------------------------- | ---: | ------------ |
| `builtin`              | встроенные плагины поставки     |    0 | включён      |
| `data`                 | `<data-directory>/plugins/`     |    1 | выключен     |
| `project:<project-id>` | `<project>/.sovereign/plugins/` |    2 | выключен     |

Меняется только путь project root. Остальное существующее поведение сохраняется:

- source-строки, ключи плагинов и записи в `preferences.json` не меняются;
- порядок перекрытия остаётся `builtin < data < project`;
- проектные плагины остаются глобальными для платформы;
- два проекта остаются источниками одного ранга, поэтому одинаковые вклады конфликтуют;
- project root создаётся только для доступного неархивного проекта;
- загрузчик просматривает непосредственные дочерние папки root, без рекурсивного обхода проекта;
- watcher, повторное обнаружение и hot reload работают по существующим правилам.

Старый путь `<project>/plugins/` сразу перестаёт обнаруживаться и наблюдаться. Платформа не переносит
файлы, не добавляет fallback и не выполняет runtime-миграцию. Существующие файлы, включая dev-данные,
не изменяются.

## Границы реализации

- В `apps/daemon/src/plugin-sources.ts` заменить только формирование project root.
- Обновить тесты project root и документацию, в которой указан старый путь.
- Не менять protocol, формат манифеста, SDK, ключи, preferences, ранги, включение, registry или
  жизненный цикл воркера.

## Критерии готовности

- Плагин из `<project>/.sovereign/plugins/<plugin>/` обнаруживается с прежним source
  `project:<project-id>` и прежней формой key.
- Плагин из `<project>/plugins/<plugin>/` не обнаруживается и не наблюдается.
- Плагин из `<data-directory>/plugins/<plugin>/` продолжает обнаруживаться как `data`.
- Архивирование или недоступность проекта снимает его единственный project root.
- `make check` проходит.

## Почему так

`.sovereign/plugins/` хранит платформенные файлы в скрытой служебной папке проекта и не занимает
его корень. Поддержка `.agents/plugins/` не требуется. Смена source или ключей не связана со сменой
пути и создала бы лишнее изменение поведения.
