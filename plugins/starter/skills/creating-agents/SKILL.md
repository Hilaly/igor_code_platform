# Создание файлового агента

Агент в Sovereign — это системный промпт плюс отбор инструментов и скилов. Его можно объявить одним
Markdown-файлом `AGENT.md` с YAML frontmatter, без программного кода. Этот скил описывает файловый
формат; программное объявление через `contribute.agent` описано в скиле `plugin-backend`.

## Расположение

Определение занимает отдельную директорию: имя директории задаёт идентичность, файл `AGENT.md` —
метаданные и инструкции, соседние файлы служат ресурсами (относительные пути разрешаются от
директории определения).

- В плагине: `<plugin-directory>/agents/<name>/AGENT.md`. Идентификатор получается с префиксом
  плагина: `<plugin-id>.<name>`. Пример: `plugins/starter/agents/generic/AGENT.md` → `starter.generic`.
- Standalone (без плагина): в корнях `<data-directory>/agents` (scope `user`) и
  `<project>/.sovereign/agents` (scope `project`). Идентификатор короткий — `<name>`. Standalone
  определения не запускают worker и не принадлежат плагину.

## Имя

Имя обязательно совпадает с именем директории. Правила: от 1 до 64 символов, латинские строчные
буквы, цифры, `_` и `-`; дефис не первый и не последний; `--` запрещён. Подчёркивание допустимо, но
у скила с `_` будет warning `nonstandard-underscore` (см. скил `creating-skills`).

## Frontmatter

YAML 1.2, повтор ключа и синтаксическая ошибка недопустимы, неизвестные поля игнорируются.

| Поле             | Обязательность | Значение                                     |
| ---------------- | -------------- | -------------------------------------------- |
| `name`           | обязательно    | имя, совпадает с директорией                 |
| `description`    | обязательно    | краткое описание агента                      |
| `tools`          | необязательно  | селектор инструментов `{ include, exclude }` |
| `skills`         | необязательно  | селектор скилов `{ include, exclude }`       |
| `model`          | необязательно  | модель по умолчанию в виде `provider/model`  |
| `thinking-level` | необязательно  | уровень reasoning по умолчанию               |

Тело после frontmatter — обязательный Markdown с инструкциями (системным промптом).

### Селекторы `tools` и `skills`

Каждый селектор — это два списка шаблонов: `include` и `exclude`.

- Метасимвол один — `*`, и он означает любой отрезок имени. Совпадение идёт по всему имени целиком,
  а не по подстроке: `read` не совпадает с `read-file`.
- Сначала применяется `include`, из результата вычитается `exclude`. **`exclude` приоритетнее.**
- Пустой `include` — это «ничего», а не «всё». Чтобы разрешить весь набор, пишут `include: ["*"]`
  явно.
- Отсутствующий селектор целиком (`tools` или `skills` не указан) становится
  `{ include: [], exclude: [] }` — тем же, что и пустой.

Инструменты собираются в рантайме из включённых плагинов, поэтому «агент без инструментов» —
законное состояние, а не ошибка конфигурации.

Скилы отбираются квалифицированным идентификатором (`github.review` для плагинного, короткий
`review` для standalone).

### Уровни thinking

`off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`.

## Ограничения

Размер `AGENT.md` — не больше 1 048 576 байт; превышение даёт диагностический код `entry-too-large`.
Символическая ссылка вместо директории определения или entry-файла запрещена (`unsupported-symlink`).

## Полный пример

```markdown
---
name: code-agent
description: Работает с кодом проекта
tools:
  include: ["*"]
  exclude: ["dangerous-*"]
skills:
  include: ["review-*"]
  exclude: []
model: anthropic/claude-opus-4-5
thinking-level: medium
---

Сначала прочитай затрагиваемые файлы, затем внеси минимальное изменение.
Проверь его запуском тестов и сборки, прежде чем сообщить о завершении.
```

## Диагностика

Определение с ошибкой не мешает остальным. Основные коды: `invalid-frontmatter`, `invalid-name`,
`name-directory-mismatch`, `missing-description`, `missing-instructions`, `invalid-selector`,
`invalid-thinking-level`. Состояние определений и диагностики видно на панели проекта
(`GET /api/projects/:id/file-resources`).
