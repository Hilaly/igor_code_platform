# Создание prompt template

Prompt template — это готовое сообщение для человека: он выбирает его через `/` и запускает обычный
турн с подставленными аргументами. Это не `SKILL.md`: скил — инструкции, которые модель читает для
работы, а шаблон — текст запроса, который получает модель.

**Главный принцип:** один шаблон — один повторяемый запрос с явным контрактом аргументов и без
скрытого состояния.

## Рабочий процесс

1. **Назови команду.** Выбери имя файла в lowercase kebab-case и проверь, что оно не занято
   `compact`, `fork`, `rename` или `archive`.
2. **Выбери область.** Для личного шаблона используй `commands/<name>.md` в директории данных; для
   правил конкретного проекта — `<project>/.sovereign/commands/<name>.md`.
3. **Опиши аргументы.** Используй `$ARGUMENTS` для всей строки или `$1`, `$2`, `$@`, `${@:N}` и
   `${@:N:L}` для позиций и срезов. Напиши в теле, что именно должен передать человек.
4. **Добавь описание.** Frontmatter необязателен; поле `description` появляется в каталоге `/`.
   Без него описание берётся из первой непустой строки тела.
5. **Проверь подстановку.** Протести пустые аргументы, пробелы и кавычки; разбор аргументов делает
   runtime, поэтому не придумывай отдельные правила quoting.
6. **Проверь область и запуск.** Убедись, что проектный шаблон перекрывает одноимённый пользовательский,
   каталог сессии показывает ожидаемую запись, а запуск создаёт обычный турн.

## Минимальный шаблон

```markdown
---
description: Разобрать изменение
---

Проверь изменение $ARGUMENTS: границы модулей, тесты и обратную совместимость.
```

## Проверка перед завершением

- файл лежит непосредственно в `commands/`, имеет расширение `.md` и не использует занятое имя;
- описание и тело объясняют ожидаемые аргументы;
- одноимённые user/project шаблоны проверены на нужный приоритет;
- каталог сессии и запуск шаблона проверены фактическим запросом, а не только чтением файла;
- нормативные детали сверены со справочником [формата шаблонов](references/file-format.md).

## Частые ошибки

- **Шаблон положили в `skills/`.** Тогда это другой ресурс и другая семантика; для инструкций модели
  используй `SKILL.md` и скил `creating-skills`.
- **Заняли имя ядра.** Файлы `compact.md`, `fork.md`, `rename.md` и `archive.md` не появляются в
  каталоге шаблонов.
- **Разбирают кавычки в браузере.** На проводе едет одна строка аргументов, а её разбор и подстановка
  принадлежат runtime.
- **Ожидают, что шаблон станет доступен модели как skill.** Он запускается человеком через `/` и
  не добавляет запись в `<available_skills>`.
